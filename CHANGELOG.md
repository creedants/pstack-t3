# Changelog

## 0.4.0 (2026-10-10)

- `land.py status` no longer accepts `Q<n>` for an entry, and the queue no longer reads, adopts, pushes, or deletes `landing/q<n>`. Entries and pull request branches are `E<n>` and `landing/e<n>` only. An entry whose candidate an older queue stored still gets its pull request on `landing/e<n>`. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- An entry whose pull request an older queue opened on `landing/q<n>` without storing its URL keeps that branch and that pull request after the upgrade. The queue opens a new pull request on `landing/e<n>`. Close the old pull request and delete the old branch by hand. An entry stored with that pull request's URL keeps it, and the queue opens no second one. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- An entry that an older queue stored with a pull request URL on `landing/q<n>` still settles when that pull request merges, on any remote. On a remote with no forge answer, a `landing/e<n>` that git reports as absent, for a pull request opened from another branch, does not block settling. A branch hidden from git on such a remote is left in place. Where the forge answers, its answer decides, and a branch it reports as existing keeps the entry waiting. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- The holder recovery from #109 now follows `--harness` and reports what it leaves. A run limited to some harnesses looks only in the skills directories of those harnesses and in the backups filed for them, which includes a harness that shares a skills directory with a selected one. An install that stops on a taken path prints its `left` lines before it exits. A run that finds only entries it leaves in place no longer creates the state directory. When a backup sits in a `.pstack-t3-*` directory and another entry has taken its backup path, uninstall restores neither, keeps the record, and prints a `kept backup` line that names both. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- `brigade.py pass record` puts every review round on record with `--report`, `--member`, and `--late`, and `close` warns about a review report with no row. A dish in progress, in review, sent back, or blocked owes a round decision at three send-backs written after its last passing verdict and its last answered round decision. While it owes one, `dish`, `brief`, and `fire` refuse another fix round on it. `86 add --dish <id> --round-budget` writes the decision, and an answer of known limits, redesign, or drop restarts the count. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- `python3 scripts/sync_upstream.py --check` reports what upstream changed since the pinned commit and changes nothing in the checkout. It reads upstream at `--ref` from a clone in a temporary directory. It prints `up to date (<commit>)` when upstream is at the pinned commit. Otherwise it prints the new commit and one row for each changed, added, or removed path under `pstack/`. Each row says what pstack-t3 does with that path today, which is `overridden by <file under t3/>`, `dropped by t3/removed.txt`, `ships unchanged`, or `not shipped`. Both cases exit 0. `--json` prints the same report as one JSON object. `--repository` reads another upstream. Both flags need `--check`. A git or network failure exits 1 with git's error. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.

- `roles.py` resolves each role to providers and models from T3's live catalog, with reasoning budgets and reported fallbacks. Default panels take one seat per model family you can run.
- `setup-pstack` writes `~/.config/pstack-t3/roles.json` from that catalog and smoke-tests each seat.
- `install.py` links the skills into Claude, Codex, Grok, and Cursor. It refuses conflicts by default, `--replace` keeps restorable backups, and `doctor` reports shadowed or stale copies.
- `pstack-author-skill` replaces Cursor's built-in skill authoring for every provider.
- The build fails on Cursor-only leftovers, broken links, invalid frontmatter, and overrides whose upstream file changed.
- Tested live in T3: `$interrogate` led by Codex with Claude, Cursor, Grok, and Codex reviewers, and `$swarm` led by Grok.
