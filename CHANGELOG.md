The arena, architect, and interrogate panels are those two seats. `unlimited` raises default seats to max. The Opus seat moves from xhigh to max. A Grok-family seat sets `fastMode` when that model declares the option. A fallback onto another family leaves `fastMode` unset. A missing preferred model falls back to the first runnable model of that family, then to this thread's model, then to the first runnable model in the catalog. The note names the role, the seat, and the replacement. `skill tests` and `verifiers` still resolve from the catalog.
- `$setup-pstack` stops before it writes a roles file or a saved catalog when the host does not expose `watch_pull_request`. It names T3 Code `0.0.46-nightly.20261005.2702` or later as the minimum.
- `$poteto-help`'s description now asks you to type `$poteto-help` with a question, and drops the broad setup triggers. The build strips `disable-model-invocation`, so a provider can still load it, like any pstack-t3 skill, when its description matches. When no roles file exists and the answer depends on which models run, it asks once whether to pick models.
- `$interrogate`, `$arena`, `$architect`, and `$swarm` pass the live catalog to `roles.py show --catalog -` on stdin, so parallel children share no temp path. `$interrogate` labels reviewers A, B, and onward, one per seat.
- For a user who already has a roles file, configured roles stay as written. Unset single roles move from `inherit` to the Opus and Grok defaults. Unset arena, architect, and interrogate panels drop the inherit seat and any Codex seat. Codex stays available as a configured choice and in `verifiers`. Without a saved catalog, an unset preferred role reports `catalog-required` where a single role used to report `inherit` and a panel `default-panel`.
- A worker's last step is `t3_thread_send` to the coordinator thread, after it writes the report. `brigade.py brief` refuses to render when no coordinator thread is recorded. `brigade.py dish <id> --reported` records that this attempt's message arrived, and a new attempt clears that mark. `brigade.py watch` prints `report written, no report-back` while the work is in progress, when the report was written for this attempt, and when the attempt is not marked reported. The report counts as written for this attempt when its modification time is at or after the attempt's start. A report left by a replaced worker does not count. The liveness check treats that line as a defect, reads the worker thread's activity to find the cause, and fires a fix at that cause. The 10-minute check stays as the backstop.
- A reporting level is set with `brigade.py open --reporting` when a coordinator opens. `brigade.py set --reporting` changes it later. The values are `every-turn`, `milestones`, and `digest`. The default is `milestones`. Opening an existing coordinator does not change its level. `status` and `walk` print the level. A `restaurant.json` with no `reporting` field reads as `milestones`. `every-turn` sends a short reply after every wake. `milestones` replies when work merges, a review sends work back or blocks it, a decision needs the user, something fails or the queue pauses, or the user sends a message. A routine wake ends with no reply, or with one line when the host requires text. `digest` replies for a decision or a failure, and sends one summary when a batch drains. A merge that does not drain the batch gets no reply. A send-back is not a failure. Every level sends the 18:00 report, acknowledges a user message, and answers a direct question. The 09:00 run is not a report.
- `brigade.py brief --fields` reads the brief fields from a JSON file, or from stdin when the argument is `-`. The object has `goal`, `acceptance`, `verify`, and `base`. `acceptance` is a list of strings. Optional `context`, `paths`, and `lease` produce the same brief as the flags. Mixing `--fields` with field flags fails and writes no brief.
- Fresh-child skill tests resolve the `skill tests` role with `roles.py`. The seat prefers a runnable model from a family other than the caller. In that pool it prefers an id token in `haiku`, `mini`, `nano`, `flash`, `lite`, `fast`, `small`, or `luna`. The next preference is the lowest default reasoning level. `delegate_task` keeps the task kind `test`. The target is omitted only when that seat is `inherit`.
- In `merge` mode, `land.py` waits for checks that have not posted yet, and that wait does not pause the queue. The first `land` that sees no posted check records the run and waits. A later `land` merges when checks are still absent. A merge is settled in the same run that makes it, including a pull request already merged at the candidate head. After the pull request merges, the queue deletes `landing/q<n>`. When that delete fails, the queue records the merge only after the forge confirms the branch is gone. HTTP 404 records the merge only when the contract remote has one push URL and that URL names the same owner and repository that `gh repo view --json nameWithOwner` resolves. HTTP 200, or any other result, leaves the entry for the next run.
- In `merge` mode, a bounce of an open pull request runs `gh pr merge --disable-auto` when that check read shows `autoMergeRequest` is not null. The pull request stays open and gets no comment. When the field is null, the bounce does not call `--disable-auto`. When the call fails, the bounce line says auto-merge is still enabled.
- In `merge` mode, a pull request with `CHANGES_REQUESTED` pauses the queue. The pause names the pull request and that requirement. A required approving review pauses the same way. Neither pause runs `gh pr merge --auto`. When the entry is already noted `merge requested by the queue`, the queue disables armed auto-merge before the pause. A failed disable is included in the pause. The pause message says to fix it, then run `land.py resume`.
- Shipping and babysit call `watch_pull_request` on every open pull request in a stack. A wake from a pull request above the frontier is reported, and that pull request stays behind the frontier. Babysit stops when that above-frontier tier is a conflict. `gateBlocker` does not report `draft-pr` while that pull request's CI is `ci-pending`, or when `allowDraft` is set.
- When `land` prints `queue busy` on a `watch_pull_request` wake, the coordinator runs `land` again, at most three more times, waiting 5 seconds before each try. Queue pushes pass `--no-follow-tags`, so a local `push.followTags` setting cannot publish a tag.
- `brigade.py set --schedule <name>=` drops that recorded schedule id. A name that is not recorded still succeeds. `brigade.py set --landing` records a mode change in `restaurant.json` after `land.py mode` switches the repository.
- Pausing writes a `Writer thread:` line with the pausing thread's id. A retry keeps a listed URL only while `list_thread_pull_requests` on that thread still shows the pull request open. A retry from another thread also calls `unwatch_pull_request` on the writer thread for each listed URL that thread still watches.
- [docs/capacity.md](docs/capacity.md) records how many idle agents this machine ran, and `scripts/measure_capacity.py` takes the samples.
- Docs name `watch_pull_request` for a wait on a pull request's checks, reviews, or conflicts, and keep `schedule_task` for a cadence. A wait whose predicate is the merge also keeps the `schedule_task` heartbeat. The README requirement is T3 Code `0.0.46-nightly.20261005.2702` or later, the minimum this project accepts for `watch_pull_request`.
- Pausing records each pull request whose watching field is true under `Paused pull request watches`. On a retry it keeps a listed URL only when `list_thread_pull_requests` still shows that pull request open, and on a new pause it replaces the list with only the pull requests watching now, then calls `unwatch_pull_request`. Session pickup calls `list_thread_pull_requests` with the prior thread's `threadId`. When it continues, it calls `link_pull_request` on the open pull requests the resumed work keeps driving, calls `watch_pull_request` on the recorded URLs, and then replaces the list with `None.`.
- Synced to upstream pstack 0.15.10 ([cursor/plugins@4e5b1cf](https://github.com/cursor/plugins/commit/4e5b1cf2ccb0ea3716f08c8ee0a5856b5ab93536)). Adds `$poteto-help`. It routes a how-do-I question to the skill or playbook and stops before doing the work.
- Opening a `$brigade` restaurant asks who lands the work. The modes are `merge`, `human`, `push`, and `local`. `auto` is the old name of `push` and is still accepted. `merge` opens a PR per change and reads posted checks before any `gh pr merge`, including `--auto`. A pending posted check waits. A failed posted check bounces. The first `land` run that sees no posted checks waits. A later run merges when checks are still absent. With no posted check, the entry waits and the queue does not pause when `gh pr merge` is refused because the base branch policy prohibits the merge. A plain merge that fails for any other reason pauses the queue, including when `--auto` reports that auto-merge is disabled. A PR already merged at the candidate head is landed before a failed check can bounce it. A failed or unreadable check read pauses the queue and does not merge. After the PR merges, the queue deletes `landing/q<n>`. `human` leaves each PR for the user to merge. `push` pushes trunk and opens no PR. `local` lands on `refs/landing/<trunk>`, which the user merges into a branch. `land.py mode` switches among `merge`, `human`, and `push` once the queue is empty. A required approving review pauses `merge` until that rule is relaxed or the mode switches to `human`. The head chef owns PR text, links, branch and worktree cleanup, and fast-forwarding a clean checkout that is on trunk.
- `$brigade` runs each worker as a worktree thread you can see and steer, and keeps reviewers as subagents. A liveness check every 10 minutes (`brigade.py watch`) is the backstop for a worker that hangs or never sends its report-back, and for work over its timebox. `brigade.py fire --paths` claims the landing lease before anything is recorded, and `brigade.py brief` renders the worker brief from the store and refuses a missing field. A decision is raised once, then only in reports, and a head chef deletes only branches it created. `land.py slot --exclusive` holds every slot so benchmarks run on a quiet machine, and `land.py submit --title --body-file` sets the PR title and body in `merge` and `human` mode. The Bridgekit pilot found that 3 of 8 workers hung open after reporting. The baseline was measured under load.
- `$landing`, a skill new to pstack-t3, lets many agents write to one repository at once. `land.py` keeps a per-repository contract (trunk, mode, checks), path leases that refuse overlapping work, and a queue that is the only writer to trunk. The queue pins each reviewed SHA, rebases it onto current trunk, refuses a change whose rebased diff differs from the reviewed one, and runs the checks in a clean worktree. State is SQLite, so a crash mid-landing is recovered from git. The modes are `merge`, `human`, `push`, and `local`. `auto` is the old name of `push` and is still accepted. `merge` and `human` open a PR on `landing/q<n>`. `push` pushes trunk only while the remote is still at the tested base. `local` lands on a ref no checkout uses. The landing mode belongs to the repository's landing contract. See [the plan](docs/landing-plan.md).
- `$brigade`, a skill new to pstack-t3. It gives a project or focus area a pinned head chef thread that holds a purpose, groups incoming requests, delegates them to poteto-mode playbooks, gates every merge on a review by another model family at the exact head SHA, and reports only what changed since the last report. `brigade.py` keeps each restaurant's state under `~/.local/state/pstack-t3/brigade/`. See [the plan](docs/brigade-plan.md).

## 0.1.0

First public release, ported from upstream pstack 0.15.6 ([cursor/plugins@23e4138](https://github.com/cursor/plugins/tree/23e4138daa01c42d4969f7a5465f82704e64f798/pstack)).

- Every pstack skill and playbook runs on T3 Code's orchestrator V2 tools: `delegate_task`, `task_status`, `t3_thread_launch`, `schedule_task`, `t3_thread_read`, the preview tools, and `link_pull_request`.
- `pstack-runtime` holds the whole Cursor-to-T3 mapping in one skill.
- `roles.py` resolves each role to providers and models from T3's live catalog, with reasoning budgets and reported fallbacks. Default panels take one seat per model family you can run.
- `setup-pstack` writes `~/.config/pstack-t3/roles.json` from that catalog and smoke-tests each seat.
- `install.py` links the skills into Claude, Codex, Grok, and Cursor. It refuses conflicts by default, `--replace` keeps restorable backups, and `doctor` reports shadowed or stale copies.
- `pstack-author-skill` replaces Cursor's built-in skill authoring for every provider.
- The build fails on Cursor-only leftovers, broken links, invalid frontmatter, and overrides whose upstream file changed.
- Tested live in T3: `$interrogate` led by Codex with Claude, Cursor, Grok, and Codex reviewers, and `$swarm` led by Grok.
