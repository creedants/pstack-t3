The entry's body has a line that reads `Based on #<n> by @<login>`, with or without a final period. The commit has a `Co-authored-by` trailer equal to its own author as `<name> <<email>>`. `<n>` is digits, and `<login>` is letters, digits, and hyphens. The body is the text of the file given to `submit --body-file`. When that text is empty or no file was given, it is the message body of the reviewed commit. Every `land.py` command except `slot` stops when the common `config` file sets `core.worktree` to a value that is not empty and where git does not find the repository. It prints `land: <config path> sets core.worktree to <value>, where git does not find this repository; remove it with git --work-tree=. config --file <config path> --unset-all core.worktree`, exits 1, and leaves the file unchanged. The command holds the path as Python's `shlex.quote` writes it when the path holds no character that ends a line for Python's `str.splitlines`. Otherwise it holds the path as a `printf %b` command substitution. In `<name>`, `<email>`, `<value>`, and the first `<config path>`, a backslash or a character that ends a line for `str.splitlines` is printed as its Python escape.
- A `land.py land` run that takes the queue lock and finds no pause now reads the configured git identity before it fetches trunk or settles an entry. The identity is `git config user.name` and `git config user.email` read in the repository, with no character removed. With no identity remembered, the run continues. It first remembers the pair when both values are non-empty, and it remembers nothing while either value is unset or empty. With an identity remembered, it pauses unless the name and the email both equal the remembered ones, character for character. Surrounding spaces and letter case count as differences. The pause prints `queue paused: the configured git identity is now <name> <<email>> and the queue last ran as <name> <<email>>; check git config --show-origin user.email in <repo>, then run land.py resume`. When either value is unset or empty after one was remembered, it prints `queue paused: the configured git identity is now unset (user.name and user.email do not both have a non-empty value) and the queue last ran as <name> <<email>>; check git config --show-origin user.email in <repo>, then run land.py resume`. That run prints no other line. It opens no pull request, pushes nothing, and changes no entry or lease. It stores the pause and logs it. While that pause stands, a later `land` that takes the queue lock prints `queue paused: ` and the stored reason, and does not read the identity. `land.py status` with no argument shows the same reason after ` Paused: `. `land.py resume` forgets the remembered identity only when the pause it clears is this one. After that `resume`, no identity is remembered. A `resume` that clears another pause, or runs with no pause set, keeps the remembered identity. In `<name>`, `<email>`, and `<repo>`, a backslash or a character that ends a line for Python's `str.splitlines` is printed as its Python escape. The help for `resume` now reads `clear a pause after you did what its reason says`.

- `land.py slot` and `land.py slot --exclusive` now take turns through OFD locks on `governor/turn`, a new file beside the slot files. A caller that cannot take its slots takes a numbered ticket and holds a lock on that ticket's byte while it waits, with no slot lock held. A later caller leaves a free slot alone when an earlier ticket that needs the same slots could take its slots at that moment. The Bridgekit pilot found that 3 of 8 workers hung open after reporting. The baseline was measured under load.
- `$landing`, a skill new to pstack-t3, lets many agents write to one repository at once. `land.py` keeps a per-repository contract (trunk, mode, checks), path leases that refuse overlapping work, and a queue that is the only writer to trunk. The queue pins each reviewed SHA, rebases it onto current trunk, refuses a change whose rebased diff differs from the reviewed one, and runs the checks in a clean worktree. State is SQLite, so a crash mid-landing is recovered from git. The modes are `merge`, `human`, `push`, and `local`. `auto` is the old name of `push` and is still accepted. `merge` and `human` open a PR on `landing/e<n>`. For one release, an open pull request already on `landing/q<n>` is adopted instead of duplicated. `push` pushes trunk only while the remote is still at the tested base. `local` lands on a ref no checkout uses. The landing mode belongs to the repository's landing contract. See [the plan](docs/landing-plan.md). Changed in 0.3.0, and listed under 0.4.0: the queue no longer adopts a pull request on `landing/q<n>`. Changed in 0.4.0: in `merge` mode it builds each queued entry on the candidate of the entry ahead of it when the merge method is `squash` or `merge`.
- `$brigade`, a skill new to pstack-t3. It gives a project or focus area a pinned head chef thread that holds a purpose, groups incoming requests, delegates them to poteto-mode playbooks, gates every merge on a review by another model family at the exact head SHA, and reports only what changed since the last report. `brigade.py` keeps each restaurant's state under `~/.local/state/pstack-t3/brigade/`. See [the plan](docs/brigade-plan.md).

## 0.1.0

First public release, ported from upstream pstack 0.15.6 ([cursor/plugins@23e4138](https://github.com/cursor/plugins/tree/23e4138daa01c42d4969f7a5465f82704e64f798/pstack)).

- Every pstack skill and playbook runs on T3 Code's orchestrator V2 tools: `delegate_task`, `task_status`, `t3_thread_launch`, `schedule_task`, `t3_thread_read`, the preview tools, and `link_pull_request`.
- `pstack-runtime` holds the whole Cursor-to-T3 mapping in one skill.
- `roles.py` resolves each role to providers and models from T3's live catalog, with reasoning budgets and reported fallbacks. Default panels take one seat per model family you can run.
- `setup-pstack` writes `~/.config/pstack-t3/roles.json` from that catalog and smoke-tests each seat.
- `install.py` links the skills into Claude, Codex, Grok, and Cursor. It refuses conflicts by default, `--replace` keeps restorable backups, and `doctor` reports shadowed or stale copies.
- `pstack-author-skill` replaces Cursor's built-in skill authoring for every provider.
- The build fails on Cursor-only leftovers, broken links, invalid frontmatter, and overrides whose upstream file changed.
- Tested live in T3: `$interrogate` led by Codex with Claude, Cursor, Grok, and Codex reviewers, and `$swarm` led by Grok.
