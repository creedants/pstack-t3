- `land.py slot`, `land.py slot --exclusive`, and the checks of `land.py land` now run on macOS. The governor took turns through Linux OFD byte locks on `governor/turn`, and on macOS that lock raised `OSError: [Errno 25] Inappropriate ioctl for device`. It now takes turns with `flock`, which locks per open file description on Linux and on macOS. The turn mutex is a `flock` on `governor/tickets.lock`. A caller that cannot take its slots creates `governor/tickets/<number>-<kind>` and holds a `flock` on it while it waits, with no slot lock held. The order of tickets, the slot files, and which caller may pass which are unchanged. A waiter that has waited 15 seconds still prints the holders of the busy slots of its kind, then again every 60 seconds. The reporting probe runs under the flock on tickets.lock, and each holder still writes its record after it takes a slot and clears that record on the way out. A killed waiter leaves its ticket file unlocked, and the next caller deletes it. A `land.py` from before this change takes turns through `governor/turn`, so it and this version honor each other's slot holds but not each other's tickets. On a filesystem where the `flock` on the turn mutex fails with `EINVAL`, `ENOTSUP`, `EOPNOTSUPP`, or `ENOLCK`, `slot` prints `land: this filesystem does not support the slot governor's ordering lock`, exits 1, and does not run the command.
- The governor tests no longer read `/proc/locks`, so they run on macOS. Two new tests queue ten free-running callers of every kind behind full slots, with one worker slot and with two, and check from the slot log that no slot is shared and no caller passes an earlier ticket it must wait for.
