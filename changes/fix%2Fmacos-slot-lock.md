- `land.py slot`, `land.py slot --exclusive`, and the checks of `land.py land` now run on macOS. The governor took turns through Linux OFD byte locks on `governor/turn`, and on macOS that lock raised `OSError: [Errno 25] Inappropriate ioctl for device`. It now takes turns with `flock`, which locks per open file description on Linux and on macOS. The turn mutex is a `flock` on `governor/tickets.lock`. A caller that cannot take its slots creates `governor/tickets/<number>-<kind>` and holds a `flock` on it while it waits, with no slot lock held. The order of tickets, the slot files, and which caller may pass which are unchanged. A waiter that has waited 15 seconds still prints the holders of the busy slots of its kind, then again every 60 seconds. The reporting probe runs under the flock on tickets.lock, and each holder still writes its record after it takes a slot and clears that record on the way out. A killed waiter leaves its ticket file unlocked, and the next caller deletes it. A `land.py` from before this change takes turns through `governor/turn`, so it and this version honor each other's slot holds but not each other's tickets. On a filesystem where the `flock` on the turn mutex fails with `EINVAL`, `ENOTSUP`, `EOPNOTSUPP`, or `ENOLCK`, `slot` prints `land: this filesystem does not support the slot governor's ordering lock`, exits 1, and does not run the command.
- The governor tests no longer read `/proc/locks`, so they run on macOS. `land.py slot`, `land.py slot --exclusive`, and each check of `land.py land` export `LAND_SLOT_FILES` to the command. The value is the names of the slot files that hold locks, sorted by name and separated by spaces. A free-running run records each held slot file. Its log rejects two intervals on one slot file, and an exclusive interval that overlaps any other caller. A stepped run frees the slots and then lets the latest parked waiter try first. That waiter may start only when no earlier conflicting ticket could take a slot.
- A ticket probe takes a shared `flock` on a read-only open. The shared lock conflicts with the waiter's exclusive `flock`. An exclusive `flock` on that read-only open raises `EBADF` where `flock` is a POSIX lock, including an NFS client, and the caller exited before the command ran. A directory entry with a link count other than 1 is not a ticket. The governor removes that name and leaves any other link in place, so a hard link to `tickets.lock` does not count as a waiter. When an admitted caller removes its ticket and the name is already gone, the command still runs. The governor assumes that only governor callers write its directory. An outside program that replaces a ticket path between the probe and the unlink can make the governor delete the replacement.
