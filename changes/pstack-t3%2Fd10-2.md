- kind feature
- `brigade.py pass hits [--last DAYS]` prints a read-only table with one row per verifier seat recorded in `pass.tsv`: rounds reviewed, passes, pass-with-edits rounds, send-backs, upheld findings, overruled findings, and the upheld rate. The window is `--last` days back from now, default 7, and the command takes only the shared read lock `pass stats` takes and writes no file
- a send-back is upheld when the same dish's next recorded round is at a different SHA, and overruled when the next recorded verdict is a pass at the same SHA or when the dish's round-budget decision was answered `known limits` or `drop` after it with no later non-member row of the dish at another SHA. A send-back that neither rule settles counts in neither. A pass-with-edits round is upheld when `edits.tsv` recorded the edits from that round's SHA and that round's report, and counts in neither otherwise. A row counts for its own verifier seat, including a `--member` row and a `--late` row. The command help states every definition, and the generated command page carries the same text
- `brigade.py close` prints a `## Reviewer hit rate (last 7 days)` section next to the send-back reasons section, with one counter line per verifier seat and the same counts, built from the same function. A week with no reviewed round prints `No reviewed rounds in the last 7 days.` `close`, `close --dry-run`, and the file `close --to-file` writes carry the same section
- rows recorded before this change load unchanged, and a `pass.tsv` row with an empty `sha` or `member` cell counts as it did before
