- `land.py status` no longer accepts `Q<n>` for an entry, and the queue no longer reads, adopts, pushes, or deletes `landing/q<n>`. Entries and pull request branches are `E<n>` and `landing/e<n>` only. An entry whose candidate an older queue stored still gets its pull request on `landing/e<n>`.
- An entry that an older queue left open on `landing/q<n>` keeps that branch and its pull request after the upgrade. The queue opens a new pull request on `landing/e<n>`. Close the old pull request and delete the old branch by hand.
- An entry that an older queue stored with a pull request URL on `landing/q<n>` still settles when that pull request merges, on any remote. A `landing/e<n>` that git says does not exist, for a pull request opened from another branch, is already gone and does not block settling.
