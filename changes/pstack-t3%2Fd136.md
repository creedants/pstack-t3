- `brigade.py` tickets carry a priority of `urgent`, `normal`, or `low`. `ticket add --priority` and `ticket set --priority` record it. A ticket that records none reads `urgent` from source `upstream`, `low` from source `report`, and `normal` from every other source.
- `brigade.py ticket list` prints the priority after the state, as in `T1 waiting normal [user] <summary>`.
- `brigade.py ticket add --paths` and `ticket set --paths` record comma-separated files and directories inside the repository on a ticket. `ticket set --paths ""` clears them.
- `brigade.py ticket add --decision` and `ticket set --decision` mark a ticket as one that asks the owner to decide. `ticket set --no-decision` removes the mark.
- `brigade.py ticket set` no longer needs `--state`. With none of `--state`, `--priority`, `--paths`, `--decision`, and `--no-decision` it exits 1. A change of priority, paths, or decision mark adds no log row.
- `brigade.py ticket move` and `ticket take` carry the ticket's recorded priority, paths, and decision mark.
- `rail.tsv` has three more columns at its end, `priority`, `paths`, and `decision`. A row written before them reads with all three empty. A `brigade.py` from before this change reads a row written by this one as malformed.
- `brigade.py set --autofire` records the auto-start level as `off`, `urgent`, `normal`, or `low`. A store that records none reads as `normal`.
- `brigade.py status` prints `workers: <running> of <cap> running, <idle> idle, auto-start: <level>` as its third line, and `watch` prints it as its first line. The executive admin's `status` does not print it.
- `brigade.py ticket add --from-report` records, on each ticket it files, the tracked files and the directories above a tracked file that the ticket's text quotes in backticks, without a trailing `:<line>` or `:<line>-<line>`. A quoted pattern that matches a tracked file records the path components before its first component with `*`, `?`, or `[`. It records no paths when git cannot list the project's tracked files.
- `brigade.py ticket paths` records the same paths from the summary of each waiting ticket that records none. `--dry-run` prints them and records nothing. It exits 1 when git cannot list the project's tracked files.
- `brigade.py next` prints the workers line, a line of counts, and one line per waiting ticket, ordered by priority, then oldest filed, then the number in the id. It starts nothing and writes no table, log row, or lease. The executive admin's store refuses it.
- `brigade.py next` prints each ticket as `startable`, `rides with <ticket>`, `blocked, <reason>`, `unknown, no paths recorded`, `decision for the owner`, `below auto-start`, or `held back, low tickets leave 1 worker idle`. The line of a startable or riding ticket is followed by its summary.
- In `brigade.py next` a ticket is startable only when it carries no decision mark, it records paths, the landing queue's `lease check` answers `free` for them, no startable ticket listed before it shares a path with it, its priority is at or above the auto-start level, and a worker is idle. A low ticket is startable only while more than 1 worker is idle.
- In `brigade.py next` a low ticket rides with a startable ticket listed before it and takes no worker when it carries no decision mark, `lease check` answers `free` for its paths, and its paths overlap that ticket's and no other startable ticket's, and that ticket is urgent or normal. A low ticket filed more than 7 days ago is marked `(over a week)`.
- `brigade.py walk` prints every other store when one store has a malformed table. That store prints `<name>: <the malformed line message>` as its one line, stderr names each malformed line, and the exit status is 1. It printed only the first malformed line.
- `brigade.py ticket add --from-report` prints `not filed, list item with no text` for a list item with no text. It printed nothing for it.
