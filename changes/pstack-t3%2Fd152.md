- `brigade.py brief` refuses a brief with no contract. `--contract <text>` or the `contract` key in the `--fields` file gives it, the brief renders it under `CONTRACT:` between `ACCEPTANCE:` and `VERIFY:`, and `contract <item>` prints the one the item's last brief stored.
- `brigade.py close` prints a warning for each item that is in review or passed and whose `reports/<item>.md` is a regular file of the store with no Claims check line.
- `brigade.py pass record` takes the verdict `pass-with-edits` with `--edits <review report>`. The item moves to sent-back, the row counts toward neither the round budget nor the move to full mode after two send-backs, and the report is refused when its `## Edits` section holds no edit or an edit that does not parse.
- `brigade.py set` takes `--build-command` and `--check-command`, and `edits verify` refuses to run until both are set, with `none` for one the project lacks.
- `brigade.py edits verify <item> --from <sha> --to <sha>` applies the round's edits to a scratch copy of the reviewed commit, runs the build command there, and compares the copy with the head at every path either commit holds where the two commits differ or the edits or the build changed the copy. When every path agrees it runs the check command there, and a run with no failure adds one row to the new `edits.tsv` table unless an equal row exists.
- `brigade.py pass record --verdict pass` without `--member` is refused while the item's last verdict row is `pass-with-edits`, unless `edits.tsv` holds a row for that round and this head or `--report` names a review report other than that round's.
