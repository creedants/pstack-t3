- `ops/t3-nightly-update.sh` and `ops/t3-archive-threads.py` are two operator scripts that run from the checkout, and nothing installs them. The first updates T3 Code, the mise tools the config lists, and `cursor-cli` when `yay` is on `PATH` and `pacman -Q cursor-cli` succeeds. It runs one step per call, `check`, `clis`, `stage`, or `restart`. The second archives finished agent threads in one T3 Code project through T3's `t3_thread_organize` tool. Each script reads its paths and lists from a `KEY=value` config file that it parses and never sources. It takes the file from `--config FILE` as its first two arguments, else from `PSTACK_T3_OPS_CONFIG` when that is not empty, else from `$XDG_CONFIG_HOME/pstack-t3/ops.conf` when `XDG_CONFIG_HOME` starts with `/`, else from `~/.config/pstack-t3/ops.conf`. It never falls back from one to the next. When the file is missing or not valid, the script prints one line on standard error and exits 78 before it does anything else, `--help` and a call with no arguments included. `ops/config.example` lists the six keys, and no key has a default. A value outside its key's characters is refused, so a path with a space in it cannot be configured. `docs/operations.md` is the runbook. `tests/test_ops.py` runs both scripts against stand-ins for `gh`, `mise`, `pacman`, `yay`, `pgrep`, `pkill`, `setsid`, `notify-send`, `strings`, `kill`, `sleep`, and T3's tool endpoint. No test covers a real restart, a real download, the unpack of a real AppImage, T3's live database, or the real tool endpoint.
