- `scripts/sync_upstream.py --merge` takes `--conflicts DIR`. For each override whose three-way merge conflicts, it writes git's conflict-marked merge to `DIR/<the override's path under t3/overrides>` and adds that path to the override's `conflict` row. The override is left as it is. The files are written before the sync writes anything in the checkout, and under `--dry-run` too. `DIR` is refused with exit status 2 when it resolves to the checkout or a path under it, and when it exists. `DIR` is not created when no override conflicts. In the saved file the `<<<<<<<` line is labelled `override` and the `>>>>>>>` line `new upstream`. `CONTRIBUTING.md` describes `--merge`, `--dry-run`, and `--conflicts` under "Syncing upstream". The upstream sync issue template asks for the rows `--merge --dry-run` prints in place of the `override drift` list.
