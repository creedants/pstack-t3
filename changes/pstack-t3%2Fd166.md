- `LandingTest.install_github_remote` in `tests/test_landing.py` writes its `git` stand-in, the `git-wrap/git` file it puts first on `PATH`, as a `/bin/sh` script instead of a Python script. The script ends every call by running the real `git` with `exec`. When its first argument is `push`, `fetch`, `ls-remote`, or `pull`, and `git remote get-url origin` exits 0 and prints a URL that starts with `https://github.com/`, it puts `-c url.<path of origin.git>/.insteadOf=<that URL>` before the arguments. It passes every other call through with its arguments unchanged. The Python script ran the real `git` with the same arguments whenever the printed URL was ASCII text with no whitespace before its final newline. It removed whitespace from both ends of the printed URL, and the `/bin/sh` script reads the URL through `$(...)`, which removes the newlines at its end.
