- `brigade.py next` reads the store and prints the steps the wake owes, then one `reply:` line. It writes nothing.
- A reply is yes when any held occasion qualifies at the reporting level, and the printed occasion is the first qualifying one. The paused-queue action is `run next --failure stuck`, and that line's condition says `--failure stuck` was not passed. A blocked review prints the condition that only the user can unblock the item, and the action names `86 add` with `--question`, `--options`, and `--default` and is not a `run`. A send-back or pass-with-edits review that meets the round budget prints no `run dish <id> --state in-progress`. A non-numeric timebox or id suffix warns on standard error and the sheet still prints. When `close` would refuse a malformed row the snapshot did not already refuse, the sheet has a see line for that row and no `run close`. A blocked line is printed only while the ticket is waiting, and the send is conditional on watch still showing the block. A reported in-progress row whose report file is absent or older than the attempt start asks the reader to read the worker and get the report, and an open decision prints no such line.
- An incoming pass-with-edits verdict does not increase the send-back count. next prints the fix-round restart for that verdict while the recorded count is under 3, and it prints no restart when that count is already 3. next does not read the report time for an item an open decision holds. When next compares a report time with a log timestamp that has no timezone, it reads that timestamp as UTC. The same read applies before next subtracts that timestamp from the current time.
