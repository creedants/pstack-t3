- `threads.tsv` holds one row per thread an item used, with the time the row was written, the item, the attempt, the role, the thread id, the seat, the start, and the end. `open` writes its header, and a store with no such file gains it on the first write that adds or closes a row. The roles are worker, fix worker, reviewer, panel member, code delegate, claims check, and architect runner, and a role that is not one of them is refused by name. Each of the seven has one writer. `dish <item> --thread <id>` writes the worker rows, and the attempt and the worker role come from the worker rows the item already holds, so attempt 1 is role worker and every later attempt is role fix worker. `pass record --reviewer-thread <id>` writes the reviewer row and takes its seat from `--verifier`. `thread <dish> --role "panel member" --thread <id> --seat <provider/model>` writes the panel member row. A `## Threads` section of `reports/<item>.md` writes the code delegate, claims check, and architect runner rows, and a report that lists no child adds no row and is not an error. A fenced block in the section is skipped, so no line inside one is read: a block opens at a line that starts, after up to three spaces, with three or more backticks holding no other backtick or with three or more tildes, and closes only at a line that is at most three spaces, at least as many of the same character, and then only spaces and tabs. A line the parser cannot read is refused by its line number and adds no row, and so is an item whose thread id the table would change, and every refusal happens before the `pass.tsv` append. `--member` takes no `--reviewer-thread`. Every write is idempotent for the same item, attempt, role, and thread. `drop`, `dish --reported`, and a `dish` update that moves the item to a state other than `in-progress` close the item's open worker rows. A `dish` update that records another worker thread closes the item's other open worker rows and leaves the new one open.
