- `scripts/check.py` `fence_findings` also checks `tests/brigade/` when that directory exists. `tests/brigade/support.py` must define `fence_git_environment` with the same syntax tree as `tests/test_landing.py`, and a module-body `setUpModule` that calls `fence_git_environment`. A missing or unreadable `tests/brigade/support.py` is named with the exception type. A missing `tests/brigade/` directory is not a finding.
- A `tests/brigade/test_*.py` file directly in that directory passes when the last binding of `setUpModule` in its module body is an import from `tests.brigade.support`, as `from .support import setUpModule` or `from tests.brigade.support import setUpModule`, or when it defines that same fence itself. A module whose body only imports classes defined in `tests/brigade/support.py` passes with no `setUpModule`. A module that binds `setUpModule` any other way, or that leaves that name unbound without being only those class imports, is named and told to import `setUpModule` from `tests/brigade/support.py`. A file that cannot be read or parsed is named with the exception type. A nested module is not checked.
