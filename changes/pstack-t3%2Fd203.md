- The landing tests remove their scratch directory after every other cleanup. `LandingTest.setUp` registers the removal with `addCleanup`, and `tearDown` only stops the environment patch. A slot holder that a test leaves running is released through its fifo and exits before the directory is removed. The removal used to run first, and that release raised `FileNotFoundError`.
- `land.py slot`, `land.py slot --exclusive`, and the checks of `land.py land` take turns with `flock`. The governor took turns with Linux OFD byte locks on `governor/turn`, which macOS rejects. The turn mutex is an exclusive `flock` on `governor/tickets.lock`. A caller that cannot take its slots creates `governor/tickets/<number>-<kind>` while it holds the mutex, and it holds an exclusive `flock` on that file while it waits. A killed waiter leaves its ticket unlocked, and the next caller removes it. `governor/turn` is never opened. The slot files, the wait lines, and the holder records are unchanged. A readable live ticket keeps its place. The exclusive cap keeps the same deadline and the same status.
- The governor is written to run on macOS. It was tested on Linux.
- An older `land.py` and this one honor each other's slot holds and not each other's tickets. A free slot can be taken ahead of the other version's waiter. Two callers of either version never hold one slot file, and a caller of one version never enters while the other version's exclusive hold has every slot. `test_an_ofd_caller_and_a_flock_caller_reorder_without_sharing_a_slot` proves this against a frozen copy of the OFD slot code.
- Only a regular file with link count 1 is a ticket. The governor reads the link count with `lstat` before it opens a single-link regular file with `O_RDONLY`, `O_NONBLOCK`, and `O_NOFOLLOW`. The probe is a shared nonblocking `flock` on that read-only descriptor. A fifo, a symlink, or an empty directory with a ticket name is removed, and a symlink's target stays. A ticket name whose inode has another link is unlinked. A link of that inode outside `tickets/` stays. A name that is not `<number>-<kind>` stays. An admitted caller whose ticket is already gone still runs its command.
- An entry the scan cannot open does not stop admission, and a second name for one ticket inode is not a waiter. The scan skips an entry whose `lstat` or `open` fails when its removal rules do not apply. It unlinks every `<number>-<kind>` name in `tickets/` for an inode it saw with more than one link in that scan, including a name reached after an earlier unlink left the count at 1. A caller sets its new ticket to mode `0o600`, so the owner can read it under any umask.
- When the `flock` on `governor/tickets.lock` fails with `EINVAL`, `ENOTSUP`, `EOPNOTSUPP`, or `ENOLCK`, `slot` prints `land: this filesystem does not support the slot governor's ordering lock`, exits 1, and does not run the command. An error from a slot file's `flock` is raised as it is.
- A command inside a hold sees `LAND_SLOT_FILES`, the locked slot filenames, sorted and separated by one space. A nested `slot` changes neither `LAND_SLOT` nor `LAND_SLOT_FILES`. The tests use the variable to attribute a log interval to a slot file. The governor tests no longer read `/proc/locks`.
- Where `os.waitid` is absent, the exclusive cap's grace polls `os.kill(pid, 0)` and does not reap the command before it sends `SIGKILL` to the group. An exited leader stays a zombie through the grace, so its process group id is not reused. When that poll raises `ProcessLookupError`, the leader is already reaped and `land.py` sends no `SIGKILL`. Where `os.waitid` exists, the grace is unchanged.
