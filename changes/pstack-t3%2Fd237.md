- A plain merge whose stderr contains `the base branch policy prohibits the merge` leaves the entry awaiting merge with the note `waiting for required checks before merging` and does not pause the queue when branch protection returns a tuple of contexts and at least one of those contexts is absent from the posted check names.
- Posted check names are the non-empty `(.name // .context)` strings from the rollup. A null or empty result of that expression stays out of the tuple and still counts in the posted total. A name that contains a quote, a backslash, a tab, or a newline stays in that tuple.
- An empty rollup does not read branch protection. The first time that entry has no recorded absent sight, the run waits before the merge when the entry is on the merge line and the pull request head is still the candidate. A run after that recorded sight waits before the merge when the entry is behind another entry and the pull request head is still the candidate. On a run after that recorded sight, the line head calls `gh pr merge --auto` when the pull request head is still the candidate and the tree of what the entry is built on still equals the trunk tree. It calls the plain merge only when that auto call exits non-zero. A blocker of `absent` on the policy refusal waits and does not read branch protection.
- When the blocker is not `absent` and the stderr contains that phrase, an unreadable protection body does not wait, and an empty `contexts` list does not wait. The queue then pauses unless the stderr also contains `Base branch was modified`.
- A plain-merge stderr without that phrase does not wait. When the plain merge exits 0, that run merges and does not read branch protection.
