- `tests/in_process.py` runs the program by the path a real interpreter records, which is `os.path.join` of the directory the invocation starts in and the program as typed, so a relative program path names the same file in the traceback, in `__file__`, and in `sys.path[0]` as a real process.
- `sys.argv[0]` for the run stays the program as typed, because a real interpreter keeps `argv[0]` as typed. `runpy.run_path` writes the path it ran into `sys.argv[0]`, so the run uses a `_TypedArgv` list that ignores writes to index 0.
- For a plain script the run starts with the script's own directory first on `sys.path`, with symlinks resolved, which `runpy.run_path` does not insert. A directory or zipfile program is a valid `sys.path` entry that `runpy.run_path` inserts itself, so the helper adds none.
- `test_a_script_run_by_a_relative_path_matches_a_real_process` runs a raising script by the relative path `scripts/runpy.py` with `cwd` set, through `invoke` and through a real interpreter, and requires the same return code, stdout, and stderr. The script prints `sys.argv[0]`, `__file__`, and `sys.path[0]`, so the compared stdout holds all three. Before the fix it fails with the relative path in the traceback and in `__file__`, and with `sys.path[0]` left at the test process's own first entry.
