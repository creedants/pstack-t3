- `tests/in_process.py` runs the program by the path a real interpreter records, which is `os.path.join` of the directory the invocation starts in and the program as typed, so a relative program path gives the same traceback and `__file__` as a real process.
- `sys.argv[0]` for the run stays the program as typed, because a real interpreter keeps `argv[0]` as typed. `runpy.run_path` writes the path it ran into `sys.argv[0]` before the script's code runs, so the run holds `sys.argv` as a `_TypedArgv` list that drops the first item assignment with the integer index 0 and applies every later assignment. A script's own write to `argv[0]` therefore lands, and only an item assignment with the integer index 0 is ever dropped.
- For a plain script the run starts with the script's own directory first on `sys.path`, with symlinks resolved, which `runpy.run_path` does not insert. A directory or zipfile program is a valid `sys.path` entry that `runpy.run_path` inserts itself, so the helper adds none.
- `test_a_script_run_by_a_relative_path_matches_a_real_process` runs a raising script by the relative path `scripts/runpy.py` with `cwd` set, through `invoke` and through a real interpreter, and requires the same return code, stdout, and stderr. The script prints `sys.argv[0]`, `__file__`, and `sys.path[0]`, so the compared stdout holds all three. Before the fix it fails with the relative path in the traceback and in `__file__`, and with `sys.path[0]` left at the test process's own first entry.
- `test_a_script_that_writes_argv_0_matches_a_real_process` runs a script that assigns `sys.argv[0]`, prints it, and exits on its value, through `invoke` and through a real interpreter, and requires the same return code, stdout, and stderr. A real interpreter returns 0 and prints the assigned value. The test passes on the merge base `67938762`, which holds no guard, and fails on the round-1 head `bfe8f242`, whose guard dropped the script's own write and left the run returning 7 and printing the program path.
