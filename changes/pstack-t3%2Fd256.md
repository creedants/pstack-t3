- `tests/brigade/support.py` gains `run_globals`. It loads a script for a test and returns the run globals of its module, so a test that reads those globals no longer needs an earlier call in the same test to have loaded the entry.
- `tests/brigade/support.py` gains `call_in_process`. It runs a script in the test process whatever `PSTACK_TEST_REAL_PROCESS` says.
- `tests/brigade/test_launch.py` and `tests/brigade/test_handoff.py` keep `call` as the default in `launch_call` and `watch_call`. `launch_call`, `assert_launch`, `assert_refused`, `watch_call`, and `assert_watch` take `in_process`, which is false unless the test passes it.
- The ten launch tests that install the fake roles globals through `install_show`, `show_payload`, or `entry_globals`, and the handoff test that patches `Path.stat`, pass `in_process=True` and run the command through `call_in_process`. The other tests of `LaunchTest` and `HandoffSizeTest` pass no flag and run their command through `call`, except `test_a_held_store_lock_refuses_launch_before_roles_py`, which calls `run` from the module globals it loaded.
- The launch tests that install a fake roles script read the seat from those globals, which a command in another interpreter does not share. The launch tests that read a roles file on disk run their command through `call`.
- A launch test sets the real-process switch, so every command the test runs through `call` starts in a separate interpreter, as it does on a push to main.
- A push to main sets the real-process switch, and a command run through `call` then runs in a separate interpreter. The ten launch and handoff tests raised `AttributeError` for `_brigade_entry` there, because nothing had loaded the entry in the test process.
