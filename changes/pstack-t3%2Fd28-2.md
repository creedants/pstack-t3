- brigade: `edits apply <item> --report <review report> --from <reviewed sha> --branch <new branch> [--worktree <path>]` applies a pass-with-edits review's edits with no worker. It refuses the whole report with one line when an old text does not occur exactly once in its file at the reviewed commit, when a path is generated or is not a regular file there, when the landing contract's generated paths cannot be read, when the applied change is over the small-fix cap, or when `--worktree` names a path that exists or lies inside the checkout, a registered worktree, or the git directory. Otherwise it creates a git worktree and the branch from the reviewed commit, applies the edits, runs the landing contract's setup and the build command, commits once through the repository's hooks with only the edited and built paths, and prints the head and the worktree path. A failure unlocks and removes the worktree it created and deletes the branch it created, and says what remains when that cannot finish. The command's own writes go to the new worktree and to git's records of that worktree and branch. The setup and build run the edited code with the caller's access, as `edits verify` and a fix worker's test runs do, so the coordinator reads the edits first. It never pushes and records no verdict, so the coordinator still runs `edits verify`, the tests, and `pass record`, and launches a fresh fix worker only when it refuses or fails
