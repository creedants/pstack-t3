- kind feature
- `check_tree` in `scripts/check.py` gains `fragment_findings`. In every `.md` file under the built `brigade/`, `brigade-admin/`, and `pstack-runtime/` skill directories, at any depth, each markdown link with a `#fragment` whose target is a `.md` file in the tree must name a heading in that target, by the slug rule `heading_slug` uses in `tests/test_pstack_t3.py`. `scripts/check.py` copies that slug function instead of importing the tests. An in-file `(#x)` link is checked against the file that holds it.
- A link with no fragment, a link inside a fenced code block, a link whose path does not resolve, a link whose target is not a `.md` file, a link whose target is outside the tree, and a link into a vendor-derived skill are not checked. A skill is vendor-derived when its directory name is a directory name under `vendor/pstack/skills`, because `vendor/pstack/` cannot be edited.
- A finding names the holding file, the line, the fragment, and the target file, and fails the build. The check reads 169 fragment links on the current tree and reports none of them.
- `tests/test_check.py` gains `FragmentCheckTest`. It has one failing and one passing case each for a link from an on-demand file to `SKILL.md`, from `SKILL.md` to an on-demand file, and in-file, one case showing a link into a vendor-derived skill is not checked, one case showing a link inside a fence is not checked, and one case showing `check_tree` reports a fragment that names no heading.
