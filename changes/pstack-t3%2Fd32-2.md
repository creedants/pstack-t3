- kind fix
- `land.py init --mode local` without `--base`, on a repository where the local trunk ref does not exist, refused the init after it had stored the contract. `status` then showed a local contract, and retrying as push was refused with no way to reset. The refusal and the `--base` lookup now run before the store is written, so a refused init leaves no contract on a first init and leaves the stored contract as it was on a re-init
- A push the remote rejects in push mode now pauses the queue with a message that has one `remote:` prefix and no doubled period, and names the resume step. Change the remote or its branch protection and run `land.py resume`. Selecting human mode with `land.py mode human` requires an empty queue. `git_reason` also drops the user and password in a URL from the text it returns, for every caller
- In local mode a bounce no longer tries to delete a landing branch from a remote, so it prints no warning about it, and `land.py prune` exits 0 without listing remote branches. In push mode a bounce of an entry with no pull request runs no remote delete, because push mode never pushes a landing branch. Merge and human mode still run both cleanup steps
- `land.py init --mode push` against a remote with no trunk branch exits 1 and says to push a first commit to that remote and trunk, then run init again, in place of git's `couldn't find remote ref`
