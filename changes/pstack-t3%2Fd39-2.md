- `land.py init --mode local --base <commit>` stored the contract and then ran `git update-ref` for the local lane, so a refused ref (for example a leftover `refs/landing/main.lock` in the repository's common git directory) left a new contract with no lane ref. The ref now moves before the contract transaction commits. A refused first init stores no contract and leaves an empty database file, and `land.py status` and every command that opens the store through its contract report no landing contract exactly as they do with no store. A later init on that store succeeds. A refused re-init leaves the stored contract as it was. The refusal is one line that names the lock file to remove when that file exists, and otherwise gives git's reason. A refused init never deletes the store, so a second init that commits at the same time keeps its contract
