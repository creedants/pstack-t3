- kind feature
- The affected-test picker runs only when a store's `restaurant.json` holds an `affectedTests` layout; with the key absent it names no test module.
- Without the key, a brief with an empty `--verify` runs the store's `checkCommand` in one foreground slot, and says `No verify command is set` when the store records no check command, including the `none` that `set --check-command none` records.
- The picker reads the stores under the store root the entry resolved from `--store`, so an explicit store keeps the layout and check command it records.
- The picker refuses a present `affectedTests` that does not parse, naming `restaurant.json`, the key, and the value, and `affected` refuses two stores that record it differently with both file paths.
- Its six keys are `always`, `workflowModule`, `entryPoints`, `helpers`, `suite`, and `python`; `suite` defaults to `python3 -m unittest discover -s tests`, and an absent `python` leaves the second-interpreter sentence out.
- `python` is an absolute path whose file name is `python<major>` or `python<major>.<minor>`, the paragraph names it by that version, and a layout that sets `python` needs a `suite` that starts with `python3`, so a layout the generator cannot honor is refused.
- The chain sentence names the `always` module and does not claim what that module checks.
- The pstack-t3 template is `{"always": "tests.test_pstack_t3", "workflowModule": "tests.test_run_tests", "entryPoints": ["t3/added/brigade/scripts/brigade.py", "t3/added/landing/scripts/land.py"], "helpers": ["tests/brigade/support.py", "tests/landing/support.py"], "suite": "python3 scripts/run_tests.py -j 8", "python": "<path to a Python 3.10 interpreter>"}`, and the same file's `buildCommand` `python3 scripts/build.py` and `checkCommand` `python3 scripts/check.py` with it preserve the current picker paragraph after replacing the interpreter placeholder with the existing interpreter path.
- The command list carries `pass record --reason` and `pass stats [--last N]`.
