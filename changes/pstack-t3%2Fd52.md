- `brigade.py open` claims its directory with `mkdir` and no `exist_ok`. The process that created the directory writes the tables, `menu.md`, and `house-rules.md`, then writes `restaurant.json`, and only then prints `opened`. Another process waits up to one second for that file and does not write those files. When the file is present but not valid JSON after that second, `open` exits 1 with `brigade: <file> is not valid JSON` and leaves the file unchanged. When that file names another project root, `open` exits 1 with `brigade: <dir> already holds a coordinator for <other root>; pick another --name` and leaves the file unchanged. After `opened` or `exists`, `open` prints each sibling on the same project root, with its thread, purpose, and what it does not take. An existing coordinator prints `thread <id> already recorded` when a thread is recorded. `brigade.py set --thread` refuses to replace that thread unless `--replace` is passed. A coordinator thread is launched only when `open` printed `opened`. The first service reruns `open` and compares sibling purposes with `menu.md`. Standing orders name the hot shared files `CHANGELOG.md`, `README.md`, and `docs/guide.md`. A change adds its changelog bullet under `changes/` and edits `README.md` or `docs/guide.md` only when its ticket is about them, or when it removes or renames something they name. Other doc edits are follow-ups batched into one docs item.
