## 0.3.0 (2026-10-09)

- `land.py` caps changes in flight per repository (`init --cap`, `cap N`), refuses to renew an expired lease into an overlap or past the cap, and adds `lease check`, `lease renew --if-live`, and `status --holder`.
- `brigade.py open` claims its directory with `mkdir` and no `exist_ok`. The process that created the directory writes the tables, `menu.md`, and `house-rules.md`, then writes `restaurant.json`, and only then prints `opened`. Another process waits up to one second for that file and does not write those files. When the file is present but not valid JSON after that second, `open` exits 1 with `brigade: <file> is not valid JSON` and leaves the file unchanged. When that file names another project root, `open` exits 1 with `brigade: <dir> already holds a coordinator for <other root>; pick another --name` and leaves the file unchanged. After `opened` or `exists`, `open` prints each sibling on the same project root, with its thread, purpose, and what it does not take. An existing coordinator prints `thread <id> already recorded` when a thread is recorded. `brigade.py set --thread` refuses to replace that thread unless `--replace` is passed. A coordinator thread is launched only when `open` printed `opened`. The first service reruns `open` and compares sibling purposes with `menu.md`. Standing orders name the hot shared files `CHANGELOG.md`, `README.md`, and `docs/guide.md`. A change adds its changelog bullet under `changes/` and edits `README.md` or `docs/guide.md` only when its ticket is about them, or when it removes or renames something they name. Other doc edits are follow-ups batched into one docs item.
- `scripts/check.py` checks a catalog heredoc only between `<<'JSON'` and a closer line that is `JSON` and nothing else. It rejects an indented closer and a closer with trailing whitespace. `$interrogate`, `$arena`, `$architect`, and `$swarm` pass a large catalog in that quoted heredoc.
- The pull request template asks for one bullet in `changes/<encoded branch>.md`, as `CONTRIBUTING.md` describes. `.gitignore` ignores `/.agents/`, `/.cursor/`, and `/skills/poteto-mode/scripts/node_modules/`.
- Each intake source has one owning brigade coordinator. `brigade.py open --intake` records it when it creates a coordinator, and `set --intake` changes it. Both refuse a source a sibling owns. `open` on an existing coordinator keeps its intake. `ticket add` refuses a source this coordinator does not own and a ref that is still live here or in a sibling, following moved tickets to the end of their chain. `ticket move <id> --to <sibling>` hands a waiting ticket to a sibling through its `inbox/`, and `ticket take` files it once, keyed by handoff id, and finishes a take a crash interrupted. Every write holds a lock on `restaurant.lock`, no command holds it while it waits on stdin or `land.py`, an append drops a killed append's unfinished tail before it writes, and a table line that does not parse stops any command run with `--at` with `brigade: <table> line <n> is malformed; fix or remove it`. `watch`, `status`, and `close` show handoffs until they are taken. Changed in 0.4.0: the malformed-table line names the store, as `brigade: <project>/<store>/<table> line <n> is malformed; fix or remove it`.
- A refused `brigade.py fire` records the paths and branch it was given, and `watch` says whether a lease, the repository cap, or the worker cap still blocks it, with the number of workers that are running. The unblocked line is a shell-quoted `fire` command. Each option is one `--name=value` word, so a value that starts with `-` stays that option's value, and the command includes `--branch` when one was recorded. `fire` leases `changes/<branch>.md` for the branch that attempt will use, including when `watch` rechecks a blocked ticket. `open --workers` and `set --workers` cap how many items can be in progress or in review, and a missing value reads as 2. `dish --lease` and `dish --paths` record a lease claimed again. A release that fails names the lease and the landing queue's diagnostic, and a failed lease check keeps that diagnostic.
- `brigade.py watch` renews the lease of every in-progress, in-review, passed, sent-back, or parked item with `land.py lease renew --if-live`, prints a line for an expired, released, or unreadable lease and for every item not merged or dropped, and updates `lastActivityAt` after a pass that renewed every live lease. For a passed or queued item it reads the queue entry at the item's exact full SHA through the new `land.py status --holder <h> --sha <sha>` filter and says whether it landed, awaits merge, bounced, or was already submitted. `dish --state dropped` releases the item's lease, and refuses without `--stopped <run id>` while a worker thread is recorded. `restaurant.json` gains `generation`: `set --thread` records 1 and `--replace` adds 1, `status` prints `owner <thread>@<generation>`, and every write then needs `--owner <thread>@<generation>`, including a ticket move's handoff into a sibling's inbox and a ticket take's inbox deletion. `land.py owner --prefix <p>/ --generation <n>` raises a floor that `lease claim`, `lease renew`, `lease release`, and `submit` enforce through `--owner`. Upgrade: a coordinator opened earlier has no `generation` and keeps working without `--owner`. Run `brigade.py set --thread <its recorded thread>` once to record generation 1, then pass `--owner <thread>@1` on every write.
- The landing mode lives only in the repository's landing contract. `brigade.py open --landing` and `set --landing` are gone, and an old `landing` field in `restaurant.json` is ignored. `brigade.py status` prints the contract's mode as `lands by <mode>`, or `no landing contract`. `walk` groups coordinators under one header per repository with that repository's `land.py status` line, shows each coordinator's leases and blocked tickets, and `walk --repo <root>` prints one repository. The guide gains a section on running several coordinators on one repository.
- `brigade.py dish --state dropped` returns the dropped item's assigned tickets to waiting, with a log row naming the item, so `ticket list` and `status` show them again and they can be fired again or dropped. `ticket list` and `walk` count a ticket blocked only while `watch`'s recheck says the block still holds, and `fire` and `watch` check the worker cap before the lease, so they name the same reason. `hang --attempt <n>` records a run an earlier attempt left open. `dish --branch` on an item with a lease prints the commands that lease the new branch's changelog fragment, or says the submitted commit lands as it is.
- In merge mode, `land.py init` reads `gh repo view --json mergeCommitAllowed,squashMergeAllowed,rebaseMergeAllowed`. With no `--merge-method` it stores the only allowed method, keeps merge when that method is still allowed, and stores squash when merge is not. It refuses a method the repository disallows and names the allowed methods. When `gh` cannot answer, it stores merge, or the method you passed. `land.py mode --merge-method` can change while entries are queued, landing, or awaiting merge. Changing the mode still needs an empty queue. A method change reads the stored mode again after that GitHub query and refuses when the mode changed while the query ran. A pause caused by a refused merge method names `land.py mode merge --merge-method` with an allowed method, then `land.py resume`. One busy entry reads as `1 entry is`. `land.py mode --help` says a mode switch needs an empty queue and a method change may run while entries are in flight.
- `worktree-audit.sh` marks `T3=yes` for a worktree under `<T3 home>/worktrees` and under `worktreesDirectory` or an array of strings in `previousWorktreesDirectories` in `<T3 home>/userdata/settings.json`. It trims `T3CODE_HOME` and those paths before expanding them, and compares an existing directory by its physical path. A filesystem root still does not count after that resolution. `--t3-worktrees` or `T3_WORKTREES` replaces the settings roots. An empty, relative, or filesystem-root setting keeps the old default. `t3/runtime.md` names `preview_hover`, `preview_drag`, `preview_select`, `preview_upload`, and `preview_dialog`, and says when to use each.
- brigade: an optional executive admin store per repository. `open --admin` claims `<project>/.admin`, which refuses `fire`, `brief`, `dish`, `pass`, and `watch`. `request` publishes a durable request into a coordinator's inbox and `request --republish` restores one a crash left unwritten, `inbox take` and `inbox done` act on it, and `ticket add --request` files one ticket per request. `rule` records, overrules, ends, and lists rulings in `rulings.tsv`. `sync` relays every coordinator's new `log.tsv` rows once through one locked snapshot reader. A relay row's id is `<store path>@<offset>` and its note is the copied row as JSON. The admin's thread is replaced only by `set --thread --replace --expect`, and a `recovering:` claim needs `--stopped`. `set --reports-to` records the thread a coordinator reports to, `status` prints the thread first, and `walk` lists the admin first.
- `land.py` carries out the executive admin's rulings. `lease reserve --for <prefix> --paths ... --ruling R<n>` holds paths for one coordinator. Every admission refuses another holder's overlap with `paths reserved for docs/ by ruling R4 until <time>`. The reservation arms only when no other holder's live lease overlaps and the cap and share have room, counts as one change in flight while the winner holds no live lease taken from it, shrinks as the winner claims, and expires 2 hours after it arms. It refuses a path list that holds the whole repository. A rerun of a fully claimed reservation prints `S<n> was claimed in full`. `lease unreserve S<n>` lifts one, and `lease list` and `lease check` show them. `share --for <prefix> <n>` limits a prefix's changes in flight with `docs/ is at its share: 2 of 2` and refuses shares that add up to more than the cap. `contest --holders <a>,<b>` holds both holders' entries out of every batch and every PR opening, `contest --settle C<n> --first <holder>` lets the first land before the other, `--settle` refuses an order that closes a cycle, and `contest --cancel` lifts the hold. Contests take the queue lock. Every ruling write requires `--owner` and refuses a generation below its prefix's floor. `init` with `--merge-method` in any mode, `mode --merge-method` in any mode, and `mode merge` now check the method against the repository's allowed methods, and `mode merge` swaps a disallowed stored method for an allowed one. In merge mode, a PR whose checks failed and whose auto-merge `gh pr merge --disable-auto` cannot turn off now pauses the queue and stays awaiting merge instead of bouncing, because it can still merge on its own. The pause says to turn auto-merge off on that PR, then run `resume` and `land`. `contest --settle` keeps the order once the first holder has an entry landing or awaiting merge.
- `land.py` reads git `HEAD` before it opens a write transaction, both when `attempt` records a landing candidate and when a human-mode entry is already on trunk. A land run that opens a pull request for an awaiting-merge entry left with none reports that pull request as opened. Adopting an existing pull request still reports it as adopted.
- `docs/guide.md` explains the optional executive admin for several coordinators on one repository. It covers how to open it, requests, its four kinds of ruling and how to overrule one, reservations, shares, contests, what you hear, and recovery. `docs/how-it-works.md` gains its row, and the README names it and says `walk` groups coordinators by repository.
- brigade's skill teaches the executive admin end to end: opening it, its services, its messages, the ruling rules and what it escalates, what it never does, recovery and retirement, and what the user hears. The admin escalates only when no rule separates the parties, records the user's answer to its own questions with `86 answer`, and passes a coordinator's reply, including a decline, to the user. The skill names which coordinator lines leave a store row that `sync` relays and which are message-only, so the admin acts on a message-only line from the message that woke it, and a coordinator whose send of one fails tells the user at every level. A coordinator with `reportsTo` sends its events to the admin, acts on its requests through `inbox take` and `inbox done`, carries out rulings and may appeal, opens contests, and keeps an hourly service. `brigade.py sync` never moves a cursor back when an older sync finishes after a newer one. On a send-back or a queue bounce the coordinator finishes with the old worker before the dish re-enters progress, so `hang` still records an open run. `watch` now prints `reported Nm ago, not in review; read the thread (<where>)`. Changed in 0.4.0: the executive admin's sections moved to the `brigade-admin` skill.
- A new landing contract does not adopt a closed or merged `landing/e<n>` pull request whose head is not this entry's candidate. It opens its own pull request. A bounced entry that is submitted again gets a new id, including in a database created before that rule. Releasing a lease, including when an entry lands, arms a reservation that was waiting only on that lease in the same transaction.
- brigade: a coordinator that reports through the executive admin ends every wake the user did not start with no text. The admin files each request the user sends as a ticket and routes it, and stays quiet at `milestones` on `blocked`, `reply`, and ruling wakes. A coordinator whose passed item depends on a sibling's unlanded item opens a contest and submits it instead of holding it, and the admin opens a contest only to carry out a queue-order ruling. When the user settles a conflict between coordinators, such as which item lands first, the admin records it as a ruling decided by `user` and carries it out. A request its coordinator already finished is never counted or handed to it again after `request --republish`, even when `inbox done` runs while the republish does.
- brigade: a worker brief says the timebox orders the work and never waives a playbook step (How, Architect, investigation, or the implementation delegate). At the limit the worker writes the report with what remains instead of skipping steps. The skill says the same when it sizes a timebox and when it reviews a report. The coordinator checks that the report names what remains. An unexplained skip, including one cited to the timebox, is a send-back.
- brigade: returning a sent-back or bounced item to in progress clears its worker thread. `dish --thread` refuses a thread an earlier attempt of that item already recorded. `watch` names an in-progress item with no worker thread, and the liveness check launches a fresh worker for that line. A send-back launches a fresh worker with `t3_thread_launch` and does not call `t3_thread_send` on the old worker.
- Playbook steps now hold under deadlines and in every code delegate. A deadline or timebox orders the work and never waives a step. The runtime's Deadlines section says so once, Autopilot-full's and Autopilot-stack's early PR targets point at it, and an agent that runs out of time reports what remains. `roles.py check-brief <file>` exits 1 and names what is missing when a poteto-mode code delegate's brief does not open with the poteto-agent persona body or lacks a `Playbook: playbooks/<name>.md` line. Feature, Refactoring, Bug fix, Perf issue, and Hillclimb, plus swarm workers and arena runners that write code for a poteto-mode playbook, run it before `delegate_task`. Architect's runner briefs list `architect/SKILL.md` as the first read, and the parent confirms that read in each runner's activity before accepting its design.
- `land.py cap N` refuses a positive cap below the current sum of shares, names that sum and each share, and writes nothing. `land.py cap 0` still clears the cap.
- A worker no longer sits idle behind a child that never finishes. The runtime tells a thread that nothing else wakes to keep its turn while a child is open, wait on it with `t3_thread_wait` in 5-minute steps, and treat a child with no new activity for 10 minutes as stalled. It takes a stalled child's written result and cancels the child, or cancels it and respawns it once. Children omit `runtimeMode`, because a child lowered to `approval-required` waits on an approval no tool can answer. How, Why, arena, interrogate, swarm, no-comments, and Orchestrate now collect their children per that rule instead of ending the turn. Brigade's liveness check reads the thread of each running worker and nudges one that has been idle for over 10 minutes with no report for the current attempt while its timebox is open, so a replacement worker is nudged even when the worker it replaced left a report. A later bullet stops the wait sooner for a child whose final result is already posted, at two minutes without activity and one recheck.
- `docs/light-mode.md` designs a light mode, one `full` or `light` setting that cuts the sub-agents and reviewers around each change while keeping tests, the build gate, the landing queue's checks, a review by another model family at every head SHA, and the owner fences. It includes a census of every spawn point with a light policy for each, one effective-mode input that `roles.py show` and `roles.py mode` share, a gate review for standalone playbooks that reuses only the latest cross-family pass at the exact head SHA while full mode keeps its patch-id policy, waivers keyed by playbook and attempt kind, escalation rules with exact path semantics and durable state, reproducible measurement commands, and an ordered build plan.
- roles.py stores full or light beside the budget, show prints mode, modeSource, and the project's escalate list, and setup-pstack asks for the mode after the budget.
- Claude Haiku 5.5 replaces Haiku 4.5 for skill tests when the test's estimated prompt is at or under 100,000 tokens. `roles.py bounded-seat` estimates it from a 41,000-token harness allowance, measured on a real T3 child, plus the brief and the files the child reads, resolves a configured seat against the catalog the way `show` does, and returns an uncapped seat when the estimate is over. It never falls back to inheriting a Haiku 5.5 thread, and it refuses a test that has no uncapped seat. `show` never returns Haiku 5.5. Every other role refuses it, including an `inherit` seat on a thread that `--parent` names as Haiku 5.5, with or without a catalog, and a malformed `--parent` is rejected. The Haiku 5.5 default bullet below removes the prompt cap and `bounded-seat` and lifts both refusals above. `show` returns Haiku 5.5 as the default for `skill tests`, `how explorer`, and `why investigators`, and every role accepts it, including an `inherit` seat on a thread that `--parent` names as Haiku 5.5, which gets the Haiku brief paragraphs.
- Light mode now changes seats. `roles.py show` takes `--brief-mode`, `--session-mode`, and `--coordinator-mode`, resolves the mode in the order brief, session, coordinator, project, user, `full`, and caps reasoning at `medium` under light when the budget is `default`. An explicit budget still wins. `show` warns on stderr when the cap could not reach an `inherit` seat. A new `roles.py mode` prints a brief's `Playbook:`, `Mode:`, `Mode source:`, `Attempt:`, and `Waived by mode:` lines. It moves an item to `full` when a lease covers a path in the project's `escalate` list, at the second send-back, or for a recorded reason, and reads waivers from `LIGHT_WAIVERS`. A stored escalate entry that normalizes to the repository root stays in the file, and roles.py mode does not treat it as a match for a tracked file. Changed in 0.5.0: the medium cap under light with budget `default` no longer applies to the `verifiers` role or the `review backups` role.
