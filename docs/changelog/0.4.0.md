## 0.4.0 (2026-10-10)

- `land.py status` no longer accepts `Q<n>` for an entry, and the queue no longer reads, adopts, pushes, or deletes `landing/q<n>`. Entries and pull request branches are `E<n>` and `landing/e<n>` only. An entry whose candidate an older queue stored still gets its pull request on `landing/e<n>`. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- An entry whose pull request an older queue opened on `landing/q<n>` without storing its URL keeps that branch and that pull request after the upgrade. The queue opens a new pull request on `landing/e<n>`. Close the old pull request and delete the old branch by hand. An entry stored with that pull request's URL keeps it, and the queue opens no second one. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- An entry that an older queue stored with a pull request URL on `landing/q<n>` still settles when that pull request merges, on any remote. On a remote with no forge answer, a `landing/e<n>` that git reports as absent, for a pull request opened from another branch, does not block settling. A branch hidden from git on such a remote is left in place. Where the forge answers, its answer decides, and a branch it reports as existing keeps the entry waiting. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- The holder recovery from #109 now follows `--harness` and reports what it leaves. A run limited to some harnesses looks only in the skills directories of those harnesses and in the backups filed for them, which includes a harness that shares a skills directory with a selected one. An install that stops on a taken path prints its `left` lines before it exits. A run that finds only entries it leaves in place no longer creates the state directory. When a backup sits in a `.pstack-t3-*` directory and another entry has taken its backup path, uninstall restores neither, keeps the record, and prints a `kept backup` line that names both. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- `brigade.py pass record` puts every review round on record with `--report`, `--member`, and `--late`, and `close` warns about a review report with no row. A dish in progress, in review, sent back, or blocked owes a round decision at three send-backs written after its last passing verdict and its last answered round decision. While it owes one, `dish`, `brief`, and `fire` refuse another fix round on it. `86 add --dish <id> --round-budget` writes the decision, and an answer of known limits, redesign, or drop restarts the count. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- `python3 scripts/sync_upstream.py --check` reports what upstream changed since the pinned commit and changes nothing in the checkout. It reads upstream at `--ref` from a clone in a temporary directory. It prints `up to date (<commit>)` when upstream is at the pinned commit. Otherwise it prints the new commit and one row for each changed, added, or removed path under `pstack/`. Each row says what pstack-t3 does with that path today, which is `overridden by <file under t3/>`, `dropped by t3/removed.txt`, `ships unchanged`, or `not shipped`. Both cases exit 0. `--json` prints the same report as one JSON object. `--repository` reads another upstream. Both flags need `--check`. A git or network failure exits 1 with git's error. This shipped in the v0.3.0 tag, and the 0.3.0 section left it out.
- The landing skill now states what the queue does with a pull request once, in a new "Pull request lifecycle" section. The mode table and the settle step link to it, and that change cut 304 words from the skill. The section describes the queue as shipped. It no longer names `status Q<n>` or the adoption and deletion of `landing/q<n>`. It says a successful `gh pr merge --auto` is followed by no plain merge, and that the pull request state read between the check read and a failed-check bounce runs only for an entry noted `merge requested by the queue`.
- `docs/cli/` is a new command-line reference, one generated page each for `activity.py`, `brigade.py`, `land.py`, and `roles.py`, plus an index at `docs/cli/README.md`. `python3 scripts/build.py` generates the pages from each script's argparse definition, with every command, flag, choice, and default. A change to one script changes only that script's page, and a renamed flag fails the tests until the build is rerun.
- docs: record the light-mode trial's results in `docs/light-mode.md`. The `medium` gate review missed a blocking finding at 3 of 8 paired commits, so the document decides that the gate keeps its full level in light mode. `roles.py show` still caps the gate at `medium` under light with budget `default` until a follow-up change. The trial's cost side stays unmeasured. Changed in 0.5.0: that follow-up landed. Light mode no longer caps the `verifiers` role or the `review backups` role at `medium`. Under light with budget `default`, `roles.py show` and `roles.py backup` resolve those seats on the configured budget. Every other role still takes the cap.
- `README.md` and `docs/guide.md` describe how install and uninstall recover an entry left in a `.pstack-t3-*` directory, with the `recovered`, `removed`, and `left` lines and the `; it is kept at` suffix. `docs/guide.md` also describes how a coordinator records each review round and the round budget at three send-backs. The guide links to the generated command-line reference in `docs/cli/` in place of restating flags, and `CONTRIBUTING.md` describes `scripts/sync_upstream.py --check`. `docs/guide.md` and `docs/landing-plan.md` no longer name `landing/q<n>`.
- runtime: follow T3 nightly 2908. Verification surfaces gain the preview tab, image, and clean-state rules, the tool-lookup rule covers every host with a tool search and tells a host with none to call the tool directly, and setup step 2 gives a concrete check for a missing Claude 5.5 model.
- `land.py lease check` no longer arms a waiting reservation, so a probe from `brigade.py watch`, `walk`, or `ticket list` cannot start a reservation's hold before the winner claims. It claims no lease, arms no reservation, starts no hold, and adds no log row. Like every command that opens the store, it upgrades an older store's schema. It still prints what `lease claim` would answer at that moment.
- `brigade.py ticket add --from-report reports/D2.md` files one waiting ticket for each follow-up in a worker's item report, with source `report` and a ref such as `perf/reports/D2.md#3`. It reads list items and paragraphs. It prints, and does not file, a paragraph that introduces a list, a paragraph after a section's last list item, and a block whose whole text is `None`, `None required`, `None needed`, `Nothing`, `Nothing needed`, `N/A`, `Not applicable`, or `No follow-ups`. It files the remaining nonempty list items and paragraphs, so a statement such as `No README edit is needed.` becomes a ticket for the coordinator to drop. It skips a follow-up whose text a ticket in any state already holds, so a second run on the same report adds nothing. It refuses a path with a `..` component, a report that is a symbolic link, and a report that resolves outside the store's `reports/`. A run changes only the ticket table, the log, and `lastActivityAt`. `--dry-run` prints what a run would add and changes no table and no log. Each worker brief now asks for a `## Follow-ups` section with one top-level list item per follow-up, and the brigade skill tells the coordinator to run the command after a passing review.
- roles: `roles.py` has one definition of a model's family, the leading word of the normalized model id. A provider path or a Bedrock prefix no longer makes a second family in the default `verifiers` panel, the built-in seat picker, the exact-model tie-break, or the `--launches-seats` pool, so the default `verifiers` panel seats one of `opencode/muse-lite-2-free` and a bare `muse-lite-2`, and a built-in seat with no exact `grok-4.7` picks `x-ai/grok-4.8` as a `missing model`.
- roles: `show` and `validate` drop the `review backups` seats that `backup` drops when no provider is out and no author is named. Those are a Codex or Cursor seat, a seat whose provider is not runnable or whose model is not in the catalog, and a repeated family. With a catalog, `show` prints the kept seats and a note with the reason for each dropped seat, and it prints no `inherit` or substituted model for this role. Without a catalog it prints `catalog-required`. `validate` prints each dropped seat as a problem and exits 1, so `write` refuses it without `--force`. A `review backups` role whose every seat is a fast Grok or Claude Haiku 4.5 seat no longer prints `unset` in `show`. It prints the config file as its source and the `skipped configured seat` notes, with `"seats": []` with a catalog and `catalog-required` without one.
- roles: the `has no seat` error names only the excluded kinds among the models it lists. For `show --launches-seats` it names the runnable providers of the launch pool, or says that none of the pool's providers can run child tasks.
- `install` and `uninstall` now exit 3 when the run printed a line that begins `skipped`. The run still does its other steps and prints its summary line before it exits. A dry run never exits 3. Lines that begin `kept` or `left`, and `nothing to link` lines, do not change the exit status. Exit 1 for a run that stops before its summary and exit 2 for a usage error are unchanged.
- When uninstall restores a backup, or removes this checkout's link from a backup that another checkout's `--replace` made, it now removes that backup's `backups/<stamp>/<harness>` directory if it is empty, then the `<stamp>` directory if that is empty. A run that finishes an interrupted restore does the same. It removes only empty directories at those two levels, inside the state directory the installer resolved. `backups/` stays, a directory that holds anything stays, a directory that another run left empty stays, and a backup recorded outside `backups/<stamp>/<harness>/` leaves its directories in place. It never follows a symlink at `backups/`, `<stamp>`, or `<harness>`, so it removes nothing through such a link. A state directory that is itself behind a symlink, such as `~/.config` or `~/.config/pstack-t3` kept in a dotfiles repository, is cleaned like any other.
- `doctor` now reads the install records. Under each selected harness it prints this checkout's recorded links that prove neither at their path nor in a recorded backup, backup records with nothing at their backup path, and owner files of other checkouts whose checkout directory is missing. Each line names a command to run, or the entry or file to delete. Every argument of a printed command is quoted for a POSIX shell, so a `--project` path with spaces or shell characters can be copied as printed. `doctor` takes no lock and writes nothing, and these lines do not change its exit status. When a record file cannot be read, `doctor` names it in one line and still runs the checks that do not need it.
- docs: the runtime states how `roles.py` compares model families after normalizing ids, and what `show`, `validate`, and `write` do with a `review backups` seat that `backup` would drop. The setup skill says `write` refuses a Cursor or Codex seat in that role unless `--force` is passed.
- brigade: the executive admin has its own skill, `brigade-admin`. It holds the sections that were under `## Executive admin` in `brigade`. They cover opening an admin, its first service, its service, its messages, rulings, what it never does, recovery and retirement, and what the user hears. The move changes no rule. The exact text of each request line the admin sends is stated once, in `brigade` under `## Reporting to an executive admin`, and `brigade-admin` names each line and links that section. References that pointed inside the old file now link the other skill, and the admin's launch message and schedule prompts say `Use the brigade-admin skill`. `brigade` keeps the coordinator's side under `## Reporting to an executive admin`, and tells an admin thread to start from `brigade-admin`, which covers an admin whose schedule prompts still name `brigade`.
- Orchestrate's sub-coordinator rule says `workState` alone decides that a sub-coordinator is unfinished, and no longer names `hasPendingChildRuns`. The authoring-a-skill playbook and pstack-author-skill say T3's `$` skill picker does not list Muse's skills. `scripts/check.py` accepts a Markdown link whose target is `t3-thread://v1/<id>`.

- roles: `validate` prints `review backups: has <n> usable seats and needs 2`, with `seat` in place of `seats` when `<n>` is 1, and exits 1 when a set `review backups` role keeps fewer than two seats, so `write` refuses that role without `--force`. `write` now prints every problem it refuses without `--force` under `error: refusing to write without --force:`, in place of `refusing to write; these seats do not match the catalog:`, and the `--force` help reads `write despite the problems validate lists, except an excluded seat`. - brigade: `ticket add --source user` with no `--ref` is refused when a `waiting` or `assigned` ticket of the same store has the same summary. A `done`, `dropped`, or `moved` ticket and a ticket of another store refuse nothing, and `--request` does not exempt the add. An add with `--ref` or from another source is not compared by summary. `--again` lifts no other refusal. `ticket add --from-report` refuses `--again`.
