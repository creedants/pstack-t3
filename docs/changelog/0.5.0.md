## 0.5.0 (2026-10-13)

- `README.md` and `docs/guide.md` carry corrections to what they say about the installer, the landing queue, `brigade.py`, and the test command.
- `brigade.py startable` holds a low ticket back from the last idle worker only while an urgent or normal ticket is waiting. In `ticket paths` and `ticket add --from-report`, a quote that is no tracked path and that, with one trailing `:<line>` or `:<line>-<line>` dropped, holds no slash, no whitespace, and none of `*`, `?`, and `[` and is no tracked path records the tracked file of that name when exactly one has that name. A file under `skills/` is not counted when a file of the same name is tracked under `t3/`.
- `brigade`: the filter of `activity.py` now also removes four kinds of text. The whole request name of a delegated task, when that name is letters and digits joined by single hyphens and stands as a whole such run with no slash that starts the word before it. An absolute path of two or more segments whose first segment starts with a hyphen or a plus sign, or that starts with two slashes. A path the run read of fewer than 4 characters, as a whole word. An email address with a quoted local part of at most 62 characters, or with a bracketed host of four numbers. The script exits with status 3 for a sub-agent row that makes a thread its own parent or ancestor even when another row gives that thread a different parent. Work items whose shortened id, summary, state, and link print alike are each listed or counted in both forms. Changed in 0.6.0: the filter also removes a non-empty value of the `threads.tsv` thread column, even when that value reads as ordinary words.
- `land.py land` reads the author of each commit between an entry's base and its reviewed commit. It does that after a replay that passes the conflict and fingerprint checks, and before it opens a pull request for an entry awaiting merge that has none. When an author name or email differs from `git config user.name` and `git config user.email` read in the repository, it bounces the entry with `bounced E<n> (<holder>): commit <sha12> has author <name> <<email>>, not the configured <name> <<email>>; recommit it as the configured author`. The check does not run when either value is unset. A replay that finds the change already in trunk is not checked. A commit with another author passes when two things hold. The entry's body has a line that reads `Based on #<n> by @<login>`, with or without a final period. The commit has a `Co-authored-by` trailer equal to its own author as `<name> <<email>>`. `<n>` is digits, and `<login>` is letters, digits, and hyphens. The body is the text of the file given to `submit --body-file`. When that text is empty or no file was given, it is the message body of the reviewed commit. Every `land.py` command except `slot` stops when the common `config` file sets `core.worktree` to a value that is not empty and where git does not find the repository. It prints `land: <config path> sets core.worktree to <value>, where git does not find this repository; remove it with git --work-tree=. config --file <config path> --unset-all core.worktree`, exits 1, and leaves the file unchanged. The command holds the path as Python's `shlex.quote` writes it when the path holds no character that ends a line for Python's `str.splitlines`. Otherwise it holds the path as a `printf %b` command substitution. In `<name>`, `<email>`, `<value>`, and the first `<config path>`, a backslash or a character that ends a line for `str.splitlines` is printed as its Python escape.
- A `land.py land` run that takes the queue lock and finds no pause now reads the configured git identity before it fetches trunk or settles an entry. The identity is `git config user.name` and `git config user.email` read in the repository, with no character removed. With no identity remembered, the run continues. It first remembers the pair when both values are non-empty, and it remembers nothing while either value is unset or empty. With an identity remembered, it pauses unless the name and the email both equal the remembered ones, character for character. Surrounding spaces and letter case count as differences. The pause prints `queue paused: the configured git identity is now <name> <<email>> and the queue last ran as <name> <<email>>; check git config --show-origin user.email in <repo>, then run land.py resume`. When either value is unset or empty after one was remembered, it prints `queue paused: the configured git identity is now unset (user.name and user.email do not both have a non-empty value) and the queue last ran as <name> <<email>>; check git config --show-origin user.email in <repo>, then run land.py resume`. That run prints no other line. It opens no pull request, pushes nothing, and changes no entry or lease. It stores the pause and logs it. While that pause stands, a later `land` that takes the queue lock prints `queue paused: ` and the stored reason, and does not read the identity. `land.py status` with no argument shows the same reason after ` Paused: `. `land.py resume` forgets the remembered identity only when the pause it clears is this one. After that `resume`, no identity is remembered. A `resume` that clears another pause, or runs with no pause set, keeps the remembered identity. In `<name>`, `<email>`, and `<repo>`, a backslash or a character that ends a line for Python's `str.splitlines` is printed as its Python escape. The help for `resume` now reads `clear a pause after you did what its reason says`.
- `scripts/run_tests.py` leaves every variable whose name starts with `GIT_` out of the environment of each worker it starts. It already left out `COLUMNS` and `LINES`. `tests/test_roles_mode.py` and `tests/test_release.py` each remove every `GIT_*` variable from `os.environ` when the module starts, and set `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` to the null device. Each restores `os.environ` when the module ends. `tests/test_release.py` builds `ENV` without the caller's `GIT_*` variables.
- `brigade.py brief` refuses a brief with no contract. `--contract <text>` or the `contract` key of the `--fields` file gives it, and the text `none` is a contract like any other. The brief renders it as given under `CONTRACT:` between `ACCEPTANCE:` and `VERIFY:`, and the new `contract <item>` command prints the one the item's last brief stored. `close` prints a warning for each item that is in review or passed and whose `reports/<item>.md` is a regular file in the store's `reports/` with no Claims check line.
- `brigade.py pass record` takes the verdict `pass-with-edits` with `--edits <review report>`, and refuses a report whose edits it cannot read, with one line that says why. The row moves the item to sent-back unless `--member` or `--late` is given, and it counts toward neither the round budget nor the move to full mode after two send-backs. The new `edits verify <item> --from <sha> --to <sha>` command applies that round's edits to a scratch copy of the reviewed commit, runs the build command there unless it is `none`, and compares the copy with the head at every path either commit holds where the two commits differ or the edits or the build changed the copy. When every path agrees it runs the check command there unless it is `none`, and a run with no failure adds one row to the new `edits.tsv` table unless an equal row exists. `set --build-command` and `--check-command` record the two commands, and `edits verify` refuses to run until both are set. `pass record --verdict pass` without `--member` is refused while the item's last row that is not a `--member` row is `pass-with-edits`, unless `edits.tsv` holds a row for that round whose `to` is the same text as `--sha`, or `--report` names a review report other than that round's.

- `ops/t3-nightly-update.sh` and `ops/t3-archive-threads.py` are two operator scripts that run from the checkout, and nothing installs them. The first updates T3 Code, the mise tools the config lists, and `cursor-cli` when `yay` is on `PATH` and `pacman -Q cursor-cli` succeeds. It runs one step per call, `check`, `clis`, `stage`, or `restart`. The second archives finished agent threads in one T3 Code project through T3's `t3_thread_organize` tool. Each script reads its paths and lists from a `KEY=value` config file that it parses and never sources. It takes the file from `--config FILE` as its first two arguments, else from `PSTACK_T3_OPS_CONFIG` when that is not empty, else from `$XDG_CONFIG_HOME/pstack-t3/ops.conf` when `XDG_CONFIG_HOME` starts with `/`, else from `~/.config/pstack-t3/ops.conf`. It never falls back from one to the next. When the file is missing or not valid, the script prints one line on standard error and exits 78 before it does anything else, `--help` and a call with no arguments included. `ops/config.example` lists the six keys, and no key has a default. A value outside its key's characters is refused, so a path with a space in it cannot be configured. `docs/operations.md` is the runbook. `tests/test_ops.py` runs both scripts against stand-ins for `gh`, `mise`, `pacman`, `yay`, `pgrep`, `pkill`, `setsid`, `notify-send`, `strings`, `kill`, `sleep`, and T3's tool endpoint. A stop that reads `land: <config path> sets core.worktree to <value>, where git does not find this repository; remove it with git --work-tree=. config --file <config path> --unset-all core.worktree` says to run the printed command and then the command again. A pause that starts `the configured git identity is now` says it is the user's call, to report it, and to run `resume` only after the config is restored or the user confirms the new identity.
