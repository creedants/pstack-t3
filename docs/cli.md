# Command-line reference

Every command and flag of the scripts pstack-t3 ships. Generated by `scripts/cli_reference.py` from each script's own argparse definition, so it never drifts.

A usage line shows a required flag bare and an optional one in brackets. `[flags]` stands for the flags of the command before it, listed in that command's section.

## brigade.py

Source: `t3/added/brigade/scripts/brigade.py`

```text
brigade.py [--store STORE] [--at AT] [--owner OWNER] <command>
```

Bookkeeping for brigade restaurants.

| Argument | Required | Choices | Default | Help |
| --- | --- | --- | --- | --- |
| `--store STORE` |  |  |  | store root (default $BRIGADE_STORE or $XDG_STATE_HOME/pstack-t3/brigade) |
| `--at AT` |  |  |  | restaurant directory (default $BRIGADE_DIR) |
| `--owner OWNER` |  |  |  | \<thread>@\<generation> from status; every write in a store with a generation needs it |

`<command>` is one of `open`, `set`, `ticket`, `fire`, `brief`, `watch`, `hang`, `dish`, `pass`, `86`, `inbox`, `request`, `rule`, `sync`, `status`, `close`, `walk`.

## land.py

| Argument | Required | Choices | Default | Help |

### land.py init

```text
land.py [flags] init --trunk TRUNK --mode MODE [--remote REMOTE] [--base BASE] [--check CHECK] [--setup SETUP] [--batch BATCH] [--timeout TIMEOUT] [--merge-method MERGE_METHOD] [--cap CAP]
```

write the repository's landing contract

| Argument | Required | Choices | Default | Help |
| --- | --- | --- | --- | --- |
| `--trunk TRUNK` | yes |  |  | branch on the remote, or a lane name in local mode |
| `--mode MODE` | yes | `human`, `merge`, `push`, `local`, `auto` |  | human: PRs you merge; merge: PRs the queue merges; push: no PRs, the queue pushes trunk; local: a lane ref |
| `--remote REMOTE` |  |  | `origin` |  |
| `--base BASE` |  |  |  | local mode: the commit the lane starts from |
| `--check CHECK` (repeatable) |  |  |  | command that must pass before landing; repeatable |
| `--setup SETUP` |  |  |  | command run before checks in the clean integration worktree, such as npm ci |
| `--batch BATCH` |  |  | `1` | entries checked together; a failed batch lands one at a time |
| `--timeout TIMEOUT` |  |  | `1800` | seconds before a check is killed |
| `--merge-method MERGE_METHOD` |  | `merge`, `squash`, `rebase` |  | merge mode: how the queue merges its PRs, checked against the repository whenever it is set. omitted in merge mode, init stores the one allowed method, or merge when gh cannot say |
| `--cap CAP` |  |  |  | most changes in flight on the repository at once; 0 clears it |

## roles.py

Source: `t3/scripts/roles.py`

```text
roles.py <command>
```

Resolve pstack-t3 roles into T3 delegate_task targets.

Roles map a pstack role name to a list of seats. A seat is "inherit" or a target {"providerInstanceId", "model", "options"} drawn from the catalog that T3's orchestrator_capabilities tool returns.

`<command>` is one of `show`, `validate`, `write`, `mode`, `check-brief`, `backup`.
