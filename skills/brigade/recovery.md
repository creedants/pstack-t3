# Recovery
## Seat mismatch
On a mismatch, stop the thread per the runtime, record nothing, and park the dish with `$B 86 add --dish <id> --question "<id>: <this thread's provider> could not pass the seat's options: <the tool error>. Move this coordinator to a provider that passes them?" --options "moved, keep parked" --default "keep parked"`. The item is then held. `$B 86 list` prints `Q<n> for <id>:`. `$B watch` prints `<id>: open decision Q<n>: ...` in place of its other lines. A second `$B 86 add --dish <id>` prints the same id and appends nothing, so never raise it again. Record every answer with `$B 86 answer Q<n> --answer "<answer>"`. Only `moved` closes the decision, matched without regard to case or a trailing period, and the command prints `Q<n> answered`. Any other answer, `keep parked` included, writes nothing and prints `Q<n> still open`, so the item stays held. Only the user can move the coordinator to a provider that passes options. Never relaunch the worker without the options.
## Contested
   **Contested.** A worker whose brief says `Mode: light` stops at a verifiable point when it finds its design contested, and reports `Contested: <reason>`, per [the runtime's Modes section](../pstack-runtime/SKILL.md#modes). Do not mark the dish in review, and spawn no verifier. Call `t3_thread_interrupt` on the old worker, then `t3_thread_wait` on the run id it returned. When the wait returns `timedOut: true`, leave everything as it is and wait again on the next service. After a terminal state, finish with the old worker per [Git and PR housekeeping](SKILL.md#git-and-pr-housekeeping). Run `$B dish <id> --mode full --reason "contested: <reason>"`. Create a new branch from the old branch's head and record it with `$B dish <id> --branch <new branch>`. Rerun `$B brief` with `--base <the old branch>` and `--context` naming the report path. When the item is held, launch no replacement worker. Otherwise launch a fresh worker per steps 4.3 and 4.4 on the new branch and the full seat its brief names. The dish stays in progress and keeps its lease. Never release or claim the lease again for this replacement, so skip the `dish --add-paths` command `dish --branch` prints. When the store sets `changeNoteDir`, the fresh worker writes its changelog bullet to the change-note fragment its brief's leased paths name. A contested report is not a send-back. It records no `pass.tsv` row and does not count toward the second send-back.
## Decision pending
   - When `pass record` or `watch` prints `<n> send-backs, decision pending`, the dish owes its round decision per [The script](SKILL.md#the-script). Follow this bullet in place of the `send-back` bullet below. Stop patching and launch no fix worker. Finish with the old worker per [Git and PR housekeeping](SKILL.md#git-and-pr-housekeeping) when the dish is sent back. Run `$B 86 add --dish <id> --round-budget` and raise that one decision in the reply. Record the user's choice with `$B 86 answer Q<n> --answer "<option>"`. On `known limits`, run step 6 again at the same head with the accepted findings listed in the verifier's brief as known limits, then land the dish on its pass. On `redesign`, follow the `send-back` bullet from `$B dish <id> --state in-progress`, and give `$B brief` a `--context` that tells the worker to run the architect skill before code and names every round's findings file. On `drop`, follow the drop steps below.
## Pass with edits
   - `pass with edits`, when the review report says `Verdict: pass with edits` and gives each edit under `## Edits`. Record the round with `$B pass record <id> --sha <reviewed sha> --verdict pass-with-edits --edits <that file> --author <provider/model> --verifier <provider/model>`. On that command `--edits` takes the place of `--report`, and passing both is refused. When `pass record` refuses the report because its edits do not parse, record that round as a `send-back` instead and follow only the `send-back` bullet. Otherwise follow the `send-back` bullet, with a `--context` that tells the fix worker to apply the edits verbatim and rebuild. When that worker reports, run `$B edits verify <id> --from <reviewed sha> --to <new head>`. When its last line is `<id>: edits verified, <reviewed sha> to <new head>`, run the verification commands that `$B affected --paths` prints for every file the fix round changed, repeating `--paths` for each changed path and running the full suite when the command reports no affected mapping, record `$B pass record <id> --sha <new head> --verdict pass --author <provider/model> --verifier <provider/model>` with a note that names the reviewed SHA, and land the dish per the `pass` bullet with no second review. When it exits 1, review the new head per step 6 and record that round with `--report <the second review's file>`. A small code fix of at most 20 changed lines lands through that same fix round and `edits verify`, which counts, for each file the edits change, the largest added plus deleted total `git diff --numstat` reports for the file at the reviewed commit against that file with the edits applied under `myers`, `minimal`, `patience`, and `histogram`, and every line of both files when git calls either one binary, and skips a path that ends in `.md` and a `.py` path whose AST is the same once its docstrings are removed. When the store sets `changeNoteDir`, it skips the fragment for the dish's current branch when the reviewed commit holds no file at that path and the new head does, and prints `skipped <path>: this round's change note` for it.
## Usage limit
   - Usage limit: when a provider in the `verifiers` role or a station's role hits its usage limit, relaunch first per [Failure handling](../pstack-runtime/SKILL.md#failure-handling). For a worker, call `t3_thread_interrupt`, then `t3_thread_wait` on the run id it returned. When the wait returns `timedOut: true`, leave the dish and wait again on the next service. After a terminal state, run `$B dish <id> --usage-limit <that seat> --role <role> --error - --catalog <file> --parent <provider/model>` with the error text on stdin. It runs `roles.py backup` with the station's role, records one cooldown row for the failed seat, and prints one next step, one of `relaunch on <provider/model>`, `relaunch on <provider/model> options <json>`, `panel on <provider/model>, <provider/model>; rule <json>`, or `parked until <end>`. When it prints `relaunch`, create a new branch from the old branch's head and record it with `$B dish <id> --branch <new branch>`. Rerun `$B brief` with `--base <the old branch>` and `--context` naming the report line. Launch a fresh worker per steps 4.3 and 4.4 with the printed seat in place of the station's seat, and pass the `options` JSON the step prints after the seat as that target's options. Never call `t3_thread_send` on the old worker. The dish keeps its lease, so skip the `dish --add-paths` command `dish --branch` prints. A held dish gets no relaunch. For a verifier, run the same dish command with `--role verifiers` and repeat `--author` for every model that wrote the diff, per [Gate review](../pstack-runtime/SKILL.md#gate-review). Read them from the worker's report: each code delegate's `providerInstanceId/model`, the worker's model when the worker wrote code, and every author an earlier attempt on this branch recorded with `$B pass record`. Never pass only the worker's model when a delegate wrote the code. When every backup family is an author family, the command parks. When it prints `relaunch`, spawn a fresh verifier per step 6 on the printed seat. When it prints `panel`, spawn one fresh verifier per step 6 on each printed seat, keep the dish in review until every one is terminal, then apply the printed rule per [Failure handling](../pstack-runtime/SKILL.md#failure-handling). Member `<n>` of round `<k>` writes its findings to `<restaurant dir>/reports/<dish>-review-<k>-panel-<n>.md`. Run `$B pass record` once for each member that returned a verdict, with that member's seat as `--verifier` and its file as `--report`. When the rule passes, record each passing member's `pass` with no other flag and every other member with `--member`. When a member reproduces a blocker, record that member's `send-back` with `--reason <reason>` and every other member with `--member`, and handle the send-back above. Every `send-back` row needs `--reason`, including a `--member` row. Choose false-wording, missing-test, wrong-behavior, out-of-lease, scope, or other. When fewer than two pass and none reproduces a blocker, record every member with `--member`, and the dish stays in review as on `park`. A relaunched or resumed worker writes its changelog bullet to the change-note fragment its brief's leased paths name, when the store sets `changeNoteDir`. A new branch never widens the lease. On `park`, launch nothing. A parked worker keeps its lease and its branch, and its dish moves to blocked. A parked verifier stays in review. A `parked until <end>` step blocks a dish in progress, changes nothing for a dish in review, and the dish relaunches after that end by the same `--resume` procedure below. Name the reset time from the error in the next report. On the first service after that time, run `roles.py backup` with `--resume`, the seat the item was approved to run on (the station's seat or the `verifiers` seat), the same `--author` flags, and `--out` for each provider whose reset has not passed. When `--resume` prints `relaunch` for the station's role, run `$B dish <id> --state in-progress`, then launch a fresh worker the same way as a relaunch above: a new branch from the old branch's head, `$B dish <id> --branch`, `$B brief --base <the old branch>`, and steps 4.3 and 4.4 on the printed seat. The branch's work carries over and the dish keeps its lease. When `--resume` prints `relaunch` for `verifiers`, spawn a fresh verifier per step 6 on the printed seat. When `--resume` prints `panel`, run the panel the same way. When it prints `park`, wait for the next reset time. Put the printed `report` line in the next report. Do not change the mode on your own. Park the choice with `$B 86 add --question "<provider> hit its usage limit. Run new work in light mode until it resets?" --options "light, full" --default "light"`. Run `$B set --mode light` only when the user answers light, or when the menu's `## Budget` says to switch, per [the runtime's Modes section](../pstack-runtime/SKILL.md#modes).
## Lease lines
   - `D3: lease L4 expired; stop its worker, then run lease renew L4`. Call `t3_thread_interrupt` on the worker thread, then `t3_thread_wait` on the run id it returned. When the wait returns `timedOut: true`, leave the lease expired and the dish as it is, run no `lease renew`, and wait again on the next service. Only after the wait reports a terminal state, run `$L lease renew L4 --owner <restaurant>/@<generation>`. It admits the lease again, or refuses with the overlap or cap message. On a refusal, park the dish with `86 add` when only the user can unblock it, and run the renew again on a later service.
   - `D3: lease L4 was released; claim again before submitting`. Claim the paths with `$L lease claim` and record it with `$B dish D3 --lease <id> --paths <paths>` before any submit.
   - `D3: could not renew L4: <error>`. The landing store did not answer. Fix that cause. `lastActivityAt` does not move until a pass renews every live lease.
## Worker ended
   - `D1: worker ended with no report; the recorded reason is <text>`. The coordinator read the worker thread and recorded the death with `$B dish D1 --worker-ended "<text>"`. The dish stays in progress and keeps its lease, branch, and thread cell. `watch` keeps printing that block until a fresh worker is recorded with `$B dish D1 --thread <id>`, or until a report for this attempt is on disk; then the report lines print in its place. Run the four steps printed under that line in order. Keep the commits on the dish branch and record no new branch, because the dish keeps its lease and the fresh worker continues in the same worktree. This attempt has no report file and no report-back mark, because the command refuses when either is present. Never call `t3_thread_send` on the dead thread.
## Skipped seat
   - `skipped <provider/model> (<cause>); run model clear <provider/model> after a smoke test passes`. Launch no worker, verifier, or code delegate on that seat while the line prints. Launch no station whose role resolves to it. After a smoke test on that seat passes, run `$B model clear <provider/model>`.
## Report written, no report-back
"report written, no report-back" is a defect. The report file exists and the dish is not marked reported. Read the worker thread with `t3_thread_read` and `view` set to "activity". Find why the message never arrived. The brief lacked the send step, the worker skipped it, `t3_thread_send` failed or went to the wrong thread, or the timebox ran out. Fire a fix at that cause, in the brief template, the skill text the worker followed, or `brigade.py`, using the **correct** skill.
