## File size limit

Agent-written files stay small enough to review. Tokens equal bytes divided by 4 with integer division. The limit is 5000 tokens per file unless --max-file-tokens or the baseline maxFileTokens sets another maximum. The queue judges only while the contract sets a maximum or the trunk tip baseline explicitly opts in with enabled true. A baseline filename alone never turns the limit on.

The committed size-baseline.json names the allowance of each larger file. The contract points at that file with sizeBaseline and may set the maximum with sizeMaxTokens, which overrides the baseline maxFileTokens. The queue reads the baseline from the actual trunk tip for every entry in a batch, not the integration head, and judges the files the rebased candidate changes at land time. Submit never judges sizes. A size violation bounces the entry with one line per over-limit file naming the path, the tokens, the allowance, and the split step. The queue refuses any entry that weakens the trunk tip policy when one exists by raising an allowance, adding a grandfathered file above the effective maximum, raising the maximum, widening skips, or removing enabled policy. Lowering is always allowed. A human raise goes through a reviewed PR that a person merges outside the queue.

Turn the limit on with `python3 <skills>/landing/scripts/land.py --repo <checkout> init --trunk main --mode <mode> --max-file-tokens 5000`. A rerun without the flags keeps the stored values. `land.py status` names the limit while the contract sets one. With the limit off, `status` and `status --json` output matches the output before the limit existed. In this repository, keep every current contract value after merge with `python3 skills/landing/scripts/land.py --repo <checkout> init --trunk main --mode merge --max-file-tokens 5000`.

Judge work with `land.py size`. The default judges changed worktree files. `--staged` judges staged files from the index. `--all` judges tracked and unignored untracked files. The first run seeds the baseline with each counted over-limit file at its current tokens. When the contract sets a maximum or `--staged` runs, seeding reads committed HEAD and never reads staged content. With no limit set, initial seeding reads the worktree and writes a baseline without `enabled`. `--shrink` lowers stored allowances that fell and never raises one. It uses the effective maximum. `--baseline` reads and writes another file instead of the contract one. `check.py` compares worktree policy against the merge-base with the trunk while the limit is on and the worktree holds a baseline. The hook compares staged policy against HEAD whenever HEAD holds a parsable baseline. The queue checks while the limit is on.

For a pstack-t3 checkout without a pre-commit hook, run `h=$(git rev-parse --git-path hooks/pre-commit) && test ! -e "$h" && printf '#!/bin/sh\nexec python3 skills/landing/scripts/land.py size --staged\n' > "$h" && chmod +x "$h"`.

Split an over-limit file before landing. Code moves one responsibility to a sibling module. Tests start a new file for the feature and share helpers. Skill and doc text moves rarely needed sections to an on-demand file with a pointer saying when to read it.

Skipped paths never count. Contract generated paths stay out. Top-level vendor tree stays out. Images stay out by extension case-insensitive, including png jpg jpeg gif webp ico svg and pdf. Lockfiles stay out by basename at any depth, including package-lock.json pnpm-lock.yaml yarn.lock go.sum and any lock file. Top-level Python cache stays out, with *.pyc at any depth. The baseline file itself stays out. This repository also skips its generated skills docs/cli and docs/skills.md through its contract generated paths and its committed baseline skip.
