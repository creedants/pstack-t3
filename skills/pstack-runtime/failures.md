# Failures

Read this file when a failed child's error names a usage limit, or after a T3 restart before you respawn any slice.

## Usage limit

Check a usage limit only for a failed child that did not return the brief's result. Read the error text from `task_status` `summary`, or from the last activity item of `t3_thread_read`. Run this command with that text on stdin. Pass `--cwd`, `--parent`, the catalog file, and the mode flag the same way as `show`. Pass `--role`, `--provider`, `--model`, and `--options` from the failed seat. For a reviewer role, repeat `--author` for every model that wrote the diff, per [Gate review](SKILL.md#gate-review): each code delegate's model, and the worker's model when the worker wrote code. A `review backups` member needs the same `--author` flags when it runs with `--resume`. Repeat `--out` for each provider already tried. The command prints `relaunch`, `panel`, `park`, or `not-usage-limit`.

  ```bash
  python3 <pstack-runtime>/scripts/roles.py backup --cwd "$PWD" --catalog <file> --parent "<inheritedProviderInstanceId>/<inheritedModel>" --role "<name>" --provider "<providerInstanceId>" --model "<model>" [--options '<json>'] [--author "<providerInstanceId>/<model>" ...] [--out "<provider>" ...] [--resume] [--brief-mode <value> | --session-mode light] <<'TEXT'
  <the error text>
  TEXT
  ```

  On `relaunch`, start a fresh child on the printed seat. Give that child a new stable `clientRequestId` ending in `-backup`. Confirm the applied options per [Delegation](delegation.md#spawn-and-collect) step 3. On `not-usage-limit`, respawn per [Failure handling](SKILL.md#failure-handling). On `park`, launch nothing. The candidates are the role's seats in the `backups` key, in order. A candidate is skipped when its provider is the failed provider, is already out, is not runnable or not in the catalog, the `exclude` list refuses it, or, for a review role, its model family wrote the diff. `review backups` has no backup. When no candidate is left, the command parks. Every family comparison in `roles.py` uses normalized model ids, per [Claude Haiku 5.5](SKILL.md#claude-haiku-55). A panel seats each family once. For a `verifiers` seat with `review backups` set, the command prints `panel` instead. On `panel`, spawn one fresh read-only child per printed seat with the same gate brief and a stable `clientRequestId` ending in `-panel-<n>`. Confirm each seat's options per [Delegation](delegation.md#spawn-and-collect) step 3. Wait until every member is terminal, even after two pass. A member that hits its usage limit runs this command with `--role "review backups"`, which parks it, and it counts as no pass. A member resumed after a reset runs `--resume --role "review backups"` with every `--author`. Without `--author` the command exits 2. It parks a member whose family is an author's, and that member counts as no pass. A member that fails otherwise respawns once. Land only if no reviewer reproduces a blocker and at least two of the panel pass. With `review backups` unset, or fewer than two usable seats, the command prints `park`. A `review backups` seat has no backup, so a `review backups` seat that hits a limit counts as no pass. A panel never seats the failed provider, seats the configured `review backups` seats it keeps, and parks when fewer than two usable seats remain. A panel reports when it drops a seat whose family is already seated. After a backup also hits a limit, pass each provider still out as `--out`. The command can choose another usable `backups` seat. After the reset time the error named, run the command with `--resume`, the parked item's original seat, the same `--author` flags, and `--out` for each provider whose reset has not passed. `--resume` reads no error text. It prints the original seat when its provider is back, and otherwise the first usable `backups` seat. A reviewer seat still skips every author's family. Start a fresh child on that seat. A parked worker keeps its lease and its branch's work. Say the printed `report` line in your report.

## After a restart

A T3 restart ends the old provider processes. Follow this section before you read a saved child's result, replace a child, or use a saved worktree path. Read `task_status` before replacing a child. A task in `working` or `waiting_for_children` can still be recovering or running, so read its child thread's recent runs and activity before launching the same slice again. A task in `result_available` finished, so read its `summary` before you respawn its slice. Durable queued messages keep their order but are held after recovery until resumed. On T3 Code 0.0.46-nightly.20261013.3080 or later, recovery cancels queued provider notifications whose buffered output was lost with the process. Pushed branches, launched threads, thread history, pull request watches, and schedules persist. Automatic restart continuation needs saved provider resume state and stops after three consecutive continuations in one chain. It does not resume an archived thread, a manually settled thread, a still-snoozed thread, a provider disabled for the project, or a turn waiting on a non-message-capable approval, question, or secret. An ended provider turn normally does not resume. On T3 Code 0.0.46-nightly.20261014.3105 or later, a completed turn can also continue when its live provider session lost an awaited monitor, provider-native subagent, or background task. A shell alone does not wake it. App-owned children recover through their own threads. On that build, `t3_thread_wait` follows the restart continuation chain and can return the continuation's run ID. Keep the original task ID and collect its result with `task_status`. A settings opt-out can disable automatic restart continuation. Read `t3_thread_read`, `task_status`, `list_thread_pull_requests`, and `list_scheduled_tasks` before recreating work after a restart. A T3-managed worktree persists unless the project enables storage cleanup. Storage cleanup removes a worktree that its rules select. It acts after the thread completes, is interrupted, is cancelled, or is rolled back. It also acts after the thread's PR merges into the default branch by squash or rebase at the worktree's head SHA. On T3 Code 0.0.46-nightly.20261015.3145 or later, a project can also remove a worktree a set number of days after its thread settles. Zero days allows removal at the first sweep past the one-minute grace in this section. Other cleanup protections still apply. No rule removes the worktree of a settled thread that still exists within a minute of that thread's last update, so the settle action runs first. The rule is off by default. Depending on the user's cleanup settings, removal takes ignored files with the worktree, such as `.env`, build output, and `.pstack/`. It can take untracked files too. Commit and push the work itself, the tracked source changes, so it outlives the worktree. Never commit an ignored or private file to keep it. Keep private files in the state directory in [Local state](SKILL.md#local-state). The branch and thread survive, and a new turn on that thread recreates the checkout. Resume through the thread's binding with `t3_thread_read`, and check that `worktreePath` exists before you use a saved path. Reattach through `t3_thread_list` and `list_scheduled_tasks`. Rebuild a PR set with [Pull requests](watching.md#pull-requests).

### Recovery by host version

- See [Host version](host.md#host-version) for the version read. When the read is absent or ambiguous, use stable behavior.
- On T3 Code 0.1.1-nightly.20261019.3360 or later, a new user message from web or mobile releases a held queue. A steer does not release it. A schedule does not release it. `t3_thread_send` does not release it. A queue held after worktree setup failed stays held until the thread has a worktree. On T3 Code 0.1.0, use the explicit Resume control. Never assume a coordinator send or heartbeat resumes a stopped queue.
- On stable, inspect affected native children and resume or restart needed work by hand. Refuse an unattended native-background recovery guarantee on stable. Name 0.1.1-nightly.20261019.3360 as the nightly these rules were read against in source.
- On stable, keep the parent turn alive while native children need T3 tools. Or use app-owned children.
- A failed root does not prove native children stopped. Keep existing checks.
- On T3 Code 0.1.1-nightly.20261019.3360 or later, worktree protection lifts only for a complete idle subagent chain with one owner and the same branch. Child threads alone no longer protect a worktree. On T3 Code 0.1.0, keep owned-worker cleanup. Make cleanup tolerant of an already removed path. Keep private state outside worktrees.
