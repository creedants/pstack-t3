# Review

Read this on a report-back or verifier completion. Read the preflight before examining the report or spawning the verifier. The core keeps step 6 start, the `t3_thread_configure` gate, step 7 `pass` filing stub, and `send-back` stub. This file holds the step 6 preflight, the verifier brief middle, the pass prefix, the full `send-back` bullet, other verdicts, and step 8.


## Review preflight

Read this before examining the report or spawning the verifier in step 6.

6. **Review.** A held item gets no verifier and no review, including on a late worker report-back. When a worker is done, read its report. When it says `Contested: <reason>` under its status line, follow **Contested** below instead of the rest of this step. Otherwise read its diff yourself. A worker's "done" is a claim. The timebox follows [Deadlines](../../pstack-runtime/SKILL.md#deadlines). The coordinator checks that the report names what remains. An unexplained skip in the report's deviations is a send-back. A skip cited to the timebox is a send-back. A step the brief's `Waived by mode:` line names is not a skip. `t3_thread_read` on the worker thread returns its `worktreePath` and branch. Run `$B dish <id> --state in-review --sha <head>`. Spawn one verifier with `delegate_task`, `mode: "async"`, from the `verifiers` role, resolved with `roles.py show --brief-mode <the item's Mode: value>`, on a model family other than the author's. Its `target` is that seat unchanged. Right after the spawn, confirm its options with `t3_thread_configure` and no `modelSelection` on the returned `childThreadId` before the verdict counts, per [the runtime's Delegation section](../../pstack-runtime/SKILL.md#delegation). On a mismatch, call `task_cancel`, record no verdict, and park the dish and record the user's answer the same way step 4.3 does. Its read-only brief: the tickets, the menu, the worktree path and, on round one, the diff at that SHA, two questions (does it work on the real surface, and does it serve the menu without scope the tickets did not ask for), and "write your findings to `<restaurant dir>/reports/<dish>-review-<k>.md`". When the brief says `Mode: light`, write the verifier's brief per [the runtime's Gate review](../../pstack-runtime/SKILL.md#gate-review) step 2, with the comment rules, the gate contract, the chosen design, and the decision trail when they apply. Then add this step's tickets, menu, and two questions below the contract. The contract forbids file edits, so write the report the verifier returns to `<restaurant dir>/reports/<dish>-review-<k>.md` yourself. In both modes, include [verdict-protocol.md](../verdict-protocol.md) in the verifier brief for the worth-a-fix-round test, the `Rare:` mark, and the `## Edits` shape. For a round after the first, the brief also carries the previous reviewed SHA, the previous round's review file, and a `FOCUS` section that carries the round rules from [Rounds after the first](../verdict-protocol.md#rounds-after-the-first), and asks for a read of the fix diff since that SHA. Copy the `scratchDir` value from `restaurant.json` into the verifier brief as the `mktemp -d -p` parent, and say so in the brief when none is set. In both modes, the verifier's brief also carries the output of `$B contract <dish>`, unchanged, under the heading `Item contract`. Below it the brief says "A change-note bullet fails this review only when it states something false. A true bullet that omits a condition is a note." The brief carries that sentence only when the store sets `changeNoteDir`. The brief also says "Never change git configuration, and never export GIT_DIR or GIT_WORK_TREE. For a scratch copy, run git worktree add --detach <a new directory outside the checkout> <sha>, or run git clone <the worktree path> <a new directory> and git checkout <sha> in the clone." For each new or changed test, ask the reviewer which change to the code makes that test fail and nothing else fail. A test with no answer is a follow-up unless it hides a defect. A round recorded with `--reviewer-thread` prints `archive thread: <id>` on standard error for that verifier thread and each helper thread the worker report `reports/<dish>.md` lists under `## Threads` that `threads.tsv` records as a child role for the attempt being reviewed, unless that id is this thread's own id, another item in flight holds it, or it is the item's current worker or an open worker row of the item. Archive each printed id with `t3_thread_organize`, `action: "archive"`, and that explicit `threadId`, one call per id. Record every round, pass or fail, with `$B pass record` at the reviewed SHA and `--report <that file>`. A send-back round also passes `--reason` with one of false-wording, missing-test, wrong-behavior, out-of-lease, scope, other. In a send-back round's verifier brief, ask the reviewer to end its blockers with one `Reason: <class>` line, using that same list. `--reason` is still required and is still the value the closeout counts. `brigade.py pass stats` counts the classes the reports name and names each send-back whose report disagrees with its `--reason`.

## Pass submit flow

   - `pass`: first run `$B ticket add --from-report reports/<dish>.md`. It files follow-ups as waiting tickets and skips text already on the rail. It prints `not filed` for a list lead-in. It prints `not filed` for prose after a section's last list item. It prints `not filed` for text after the word on a follow-ups heading line. It prints `not filed` for a deeper heading that does not start with follow-ups, with that heading's text when it has any. It prints `not filed` for a block whose whole text is `None`, `None required`, `None needed`, `Nothing`, `Nothing needed`, `N/A`, `Not applicable`, or `No follow-ups`, in any letter case, with or without list markers, a final period, and `*`, `_`, or backtick marks around it. A dry run prints `would add` from, `would note`, `already noted`, `skipped`, and `not filed`. A real run prints `added from`, `noted`, `already noted`, and the same `skipped` and `not filed`. A `not filed` line needs nothing. A `skipped` line needs nothing. A real run's `noted` follow-up already went to `notes.tsv`, so file it by hand only when it is worth an item with `$B ticket add --summary "..." --kind <kind>`. A dry run's `would note` line would go to `notes.tsv`. Drop a ticket that is not worth an item with `$B ticket set <id> --state dropped`, or fire it with related tickets as one dish per step 3. When the dish depends on another coordinator's item that has not landed and `$B status` prints `reports to <thread>`, never hold it outside the queue. Follow [Contests](../admin-reporting.md#contests) before you submit.

Then submit as below. Write the PR title and body (what changed, the measured effect, how it was verified) to `<restaurant dir>/prs/<dish>.md`. When `prCredit` is on, run `$B credit <dish> --coordinator <your provider/model>` and put its line as the last line of that file before submitting. Then `$L submit --holder <restaurant>/<dish> --branch <b> --sha <head> --lease L<n> --reviewer <provider/model> --title "..." --body-file <restaurant dir>/prs/<dish>.md`, then `$B dish <id> --state queued`, then `$L land`. When it lands, `$B dish <id> --state merged`. In `merge` and `human` mode it opens a PR first. Record it with `$B dish <id> --pr <url>`, link it with `link_pull_request`, and call `watch_pull_request` on it per [Pull request watching](../../pstack-runtime/SKILL.md#pull-request-watching). This head chef thread owns the PR. On each wake, run `$L land`. Keep the watch while the dish is queued or awaiting merge. A reply, or a wake with no reply, keeps the watch. Call `unwatch_pull_request` only when this thread stops driving that PR. Driving stops when the dish is dropped, when its PR closes, when the queue bounces it and leaves the PR open, or when the restaurant closes. If this thread is settled, call `t3_thread_organize` with `action: "unsettle"` (no `threadId`, acting on the caller on purpose) before the next `watch_pull_request`. This thread is pinned, so a merge does not auto-settle it. Mark the dish merged when a later `land` reports it landed.


   - Bounced by the queue: the lease is active again. Call `unwatch_pull_request` on the PR the bounce left open. Finish with the old worker per [Git and PR housekeeping](../SKILL.md#git-and-pr-housekeeping). Then run `$B dish <id> --state in-progress`, because `brief` refuses a queued dish. That command clears the recorded worker thread. Rerun `$B brief` with `--context` naming the bounce reason and current trunk. Launch a fresh worker per steps 4.3 and 4.4, unless the item is held. A conflict or a changed rebase needs a new review.


   - `pass with edits`, when the review report says `Verdict: pass with edits`, do not record a `pass-with-edits` verdict with `--report`. Follow [Pass with edits](../recovery.md#pass-with-edits) before recording this round at the reviewed SHA. Before any fix worker, run `$B edits apply <id> --report <that file> --from <reviewed SHA> --branch <new branch>`. It applies the edits on a new branch with no worker. Its setup and build run the edited code with your access, so read the edits first. Run `$B edits verify`, the verification commands, and `$B pass record` on the head it prints, as the recovery section says. Launch a fresh fix worker only when it refuses or fails. A safety, privacy, or integrity change still gets a second review. A small code fix of at most 20 changed lines lands through that same fix round and `edits verify`, which counts, for each file the edits change, the largest added plus deleted total `git diff --numstat` reports for the file at the reviewed commit against that file with the edits applied under `myers`, `minimal`, `patience`, and `histogram`, and every line of both files when git calls either one binary, and skips a path that ends in `.md` and a `.py` path whose AST is the same once its docstrings are removed. `edits verify` runs the landing contract's setup command in the replay copy after the edits are applied and before the build and check commands when the contract records one, and the setup string runs through a shell while the build and check commands do not.


## Send-back detail

Read this before creating the fix worker in step 7.

   - `send-back`: finish with the old worker per [Git and PR housekeeping](../SKILL.md#git-and-pr-housekeeping). Then `$B dish <id> --state in-progress`, which clears the recorded worker thread. Rerun `$B brief` with `--base <the old branch head>`. It adds the verifier's findings file and the `Attempt: fix` lines, per [the runtime's Modes section](../../pstack-runtime/SKILL.md#modes). Every send-back launches a fresh worker per steps 4.3 and 4.4, on a new branch from the old branch's head, however small the fix, unless the item is held. Never call `t3_thread_send` on the old worker. `$B dish <id> --thread <new>` prints `archive thread: <id>` on standard error for the worker it replaced, unless that id is this thread's own id or another item in flight holds it. Archive each printed id with `t3_thread_organize`, `action: "archive"`, and that explicit `threadId`, one call per id.


   - `blocked`: `86 add` if only the user can unblock it. Otherwise fix the environment and run the pass again.


   - Usage limit: when a provider in the `verifiers` role or a station's role hits its usage limit, launch no replacement before following [Usage limit](../recovery.md#usage-limit). For a worker, run steps 1 and 2 of the three drop steps in step 7 without step 3 and wait for a terminal state before any replacement. For a worker or a verifier, run `$B dish <id> --usage-limit <failed seat> --role <role> --error - --catalog <file> --parent <provider/model>` with the error text on stdin, and repeat `--author` for every model that wrote the diff when the role is `verifiers`. It records the cooldown and prints one next step. Do not change the mode on your own.


- Drop a dish in three steps. A requested interrupt is not a stop. `t3_thread_interrupt` can return `status: "interrupt_requested"` while the worker's run goes on.
     1. Call `t3_thread_interrupt` on its worker thread.
     2. Call `t3_thread_wait` on the run id it returned, or on the thread when it returned none. When the wait returns `timedOut: true`, leave the dish in its state. `watch` keeps its lease renewing. Wait again on the next service.
     3. When the wait reports a terminal state, run `$B dish <id> --state dropped --stopped <run id>`, or `--stopped idle` when the wait reported an idle thread. That releases its lease.


- After a dish merges or is dropped, clean up per [Git and PR housekeeping](../SKILL.md#git-and-pr-housekeeping). A send-back or a bounce follows that same finish above, and does not enter in progress while the old worker's run is still open or its child work is still pending. After a send-back, delete the old branch per that section once the fresh worker is launched. `$B dish <id> --state merged` prints `archive thread: <id>` on standard error for every worker thread the item used, except this thread's own id and a thread another item in flight holds. `$B dish <id> --state dropped` prints `archive thread: <id>` on standard error for worker threads observed before the lease release, except this thread's own id and a thread another item in flight holds. At recheck, it omits any id with an `(attempt, role, thread)` worker row identity absent from the snapshot. It also omits the rechecked dish thread cell's id when that cell is non-empty and differs from the observed cell. A rebind with neither change can still be announced. Archive each printed id with `t3_thread_organize`, `action: "archive"`, and that explicit `threadId`, one call per id. A coordinator thread that no printed line names is archived by hand with `t3_thread_organize`, `action: "archive"`, and that explicit `threadId`.


8. **Fix the recipe.** When two dishes repeat the same mistake, fire a dish that runs the **correct** skill to make it impossible (lint, type, test, or skill). Run the **reflect** skill over this restaurant's threads once a week. Skip it while `roles.py mode --cwd <project root>`, with `--coordinator-mode` set to the `restaurant.json` mode when one is recorded, prints `Mode: light`, per [the runtime's Modes section](../../pstack-runtime/SKILL.md#modes).
