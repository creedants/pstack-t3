# Review

Read this on a report-back or verifier completion. The core keeps step 6 start, the `t3_thread_configuration` gate, step 7 `pass` filing, stub, and `send-back`. This file holds the verifier brief middle, other verdicts, and step 8.


## Verifier brief middle

Its read-only brief: the tickets, the menu, the worktree path and, on round one, the diff at that SHA, two questions (does it work on the real surface, and does it serve the menu without scope the tickets did not ask for), and "write your findings to `<restaurant dir>/reports/<dish>-review-<k>.md`". When the brief says `Mode: light`, write the verifier's brief per [the runtime's Gate review](../../pstack-runtime/SKILL.md#gate-review) step 2, with the comment rules, the gate contract, the chosen design, and the decision trail when they apply. Then add this step's tickets, menu, and two questions below the contract. The contract forbids file edits, so write the report the verifier returns to `<restaurant dir>/reports/<dish>-review-<k>.md` yourself. In both modes, include [verdict-protocol.md](../verdict-protocol.md) in the verifier brief for the worth-a-fix-round test, the `Rare:` mark, and the `## Edits` shape. For a round after the first, the brief also carries the previous reviewed SHA, the previous round's review file, and a `FOCUS` section that carries the round rules from [Rounds after the first](../verdict-protocol.md#rounds-after-the-first), and asks for a read of the fix diff since that SHA. Copy the `scratchDir` value from `restaurant.json` into the verifier brief as the `mktemp -d -p` parent, and say so in the brief when none is set. In both modes, the verifier's brief also carries the output of `$B contract <dish>`, unchanged, under the heading `Item contract`. Below it the brief says "A change-note bullet fails this review only when it states something false. A true bullet that omits a condition is a note." The brief carries that sentence only when the store sets `changeNoteDir`. The brief also says "Never change git configuration, and never export GIT_DIR or GIT_WORK_TREE. For a scratch copy, run git worktree add --detach <a new directory outside the checkout> <sha>, or run git clone <the worktree path> <a new directory> and git checkout <sha> in the clone." For each new or changed test, ask the reviewer which change to the code makes that test fail and nothing else fail. A test with no answer is a follow-up unless it hides a defect. A round recorded with `--reviewer-thread` prints `archive thread: <id>` on standard error for that verifier thread, unless that id is this thread's own id, another item in flight holds it, or it is the item's current worker or an open worker row of the item.


## Pass submit flow

Then submit as below. Write the PR title and body (what changed, the measured effect, how it was verified) to `<restaurant dir>/prs/<dish>.md`, then `$L submit --holder <restaurant>/<dish> --branch <b> --sha <head> --lease L<n> --reviewer <provider/model> --title "..." --body-file <restaurant dir>/prs/<dish>.md`, then `$B dish <id> --state queued`, then `$L land`. When it lands, `$B dish <id> --state merged`. In `merge` and `human` mode it opens a PR first. Record it with `$B dish <id> --pr <url>`, link it with `link_pull_request`, and call `watch_pull_request` on it per [Pull request watching](../../pstack-runtime/SKILL.md#pull-request-watching). This head chef thread owns the PR. On each wake, run `$L land`. Keep the watch while the dish is queued or awaiting merge. A reply, or a wake with no reply, keeps the watch. Call `unwatch_pull_request` only when this thread stops driving that PR. Driving stops when the dish is dropped, when its PR closes, when the queue bounces it and leaves the PR open, or when the restaurant closes. If this thread is settled, call `t3_thread_organize` with `action: "unsettle"` (no `threadId`, acting on the caller on purpose) before the next `watch_pull_request`. This thread is pinned, so a merge does not auto-settle it. Mark the dish merged when a later `land` reports it landed.


   - Bounced by the queue: the lease is active again. Call `unwatch_pull_request` on the PR the bounce left open. Finish with the old worker per [Git and PR housekeeping](../SKILL.md#git-and-pr-housekeeping). Then run `$B dish <id> --state in-progress`, because `brief` refuses a queued dish. That command clears the recorded worker thread. Rerun `$B brief` with `--context` naming the bounce reason and current trunk. Launch a fresh worker per steps 4.3 and 4.4, unless the item is held. A conflict or a changed rebase needs a new review.


   - `pass with edits`, when the review report says `Verdict: pass with edits`, do not record a `pass-with-edits` verdict with `--report`. Follow [Pass with edits](../recovery.md#pass-with-edits) before recording this round at the reviewed SHA.


   - `blocked`: `86 add` if only the user can unblock it. Otherwise fix the environment and run the pass again.


   - Usage limit: when a provider in the `verifiers` role or a station's role hits its usage limit, launch no replacement before following [Usage limit](../recovery.md#usage-limit). For a worker, run steps 1 and 2 of the three drop steps in step 7 without step 3 and wait for a terminal state before any replacement. Do not change the mode on your own.


- Drop a dish in three steps. A requested interrupt is not a stop. `t3_thread_interrupt` can return `status: "interrupt_requested"` while the worker's run goes on.
     1. Call `t3_thread_interrupt` on its worker thread.
     2. Call `t3_thread_wait` on the run id it returned, or on the thread when it returned none. When the wait returns `timedOut: true`, leave the dish in its state. `watch` keeps its lease renewing. Wait again on the next service.
     3. When the wait reports a terminal state, run `$B dish <id> --state dropped --stopped <run id>`, or `--stopped idle` when the wait reported an idle thread. That releases its lease.


- After a dish merges or is dropped, clean up per [Git and PR housekeeping](../SKILL.md#git-and-pr-housekeeping). A send-back or a bounce follows that same finish above, and does not enter in progress while the old worker's run is still open or its child work is still pending. After a send-back, delete the old branch per that section once the fresh worker is launched. `$B dish <id> --state merged` prints `archive thread: <id>` on standard error for every worker thread the item used, except this thread's own id and a thread another item in flight holds. `$B dish <id> --state dropped` prints `archive thread: <id>` on standard error for worker threads observed before the lease release, except this thread's own id and a thread another item in flight holds. At recheck, it omits any id with an `(attempt, role, thread)` worker row identity absent from the snapshot. It also omits the rechecked dish thread cell's id when that cell is non-empty and differs from the observed cell. A rebind with neither change can still be announced. Archive each printed id with `t3_thread_organize`, `action: "archive"`, and that explicit `threadId`, one call per id. The nightly sweep with `ops/t3-archive-threads.py` stays the backstop for a thread no printed line names.


8. **Fix the recipe.** When two dishes repeat the same mistake, fire a dish that runs the **correct** skill to make it impossible (lint, type, test, or skill). Run the **reflect** skill over this restaurant's threads once a week. Skip it while `roles.py mode --cwd <project root>`, with `--coordinator-mode` set to the `restaurant.json` mode when one is recorded, prints `Mode: light`, per [the runtime's Modes section](../../pstack-runtime/SKILL.md#modes).
