# Service

Read this at every service before step 1 in [Run a service](../SKILL.md#run-a-service). The core keeps the wake line, short stubs, the launch line, step 4.4, and the verdict stubs. This file holds steps 0 to 5 detail, 4.1, 4.2, 4.3, refill, and end turn.


0. **Next.** Run `$B next` first. Pass `user` for a user message. Pass `report-back <dish>` for a worker report. Pass `review <dish> --verdict <verdict>` for a verifier completion. Pass `liveness`, `intake`, `morning`, or `evening` for the matching schedule. Leave the wake off for the landing drain schedule and follow [First service](../SKILL.md#first-service). Pass `checks <dish> --result pass|fail` when a `watch_pull_request` wake reports failed checks or passed required checks. For other PR-watch events, leave the wake off, read the PR event, and follow [First service](../SKILL.md#first-service). Pass `merge <dish>` when land may have landed the dish. Leave the wake off when its cause is unknown. Pass `--failure` for a known failure. Pass `--unsent` for an unsent admin line. Its output names the steps this wake owes and whether it is a reply.


1. **Read.** `menu.md`, `house-rules.md`, `$B status`, `$B 86 list`. Re-read the menu every service. It is the purpose every decision answers to. `$B status` prints `thread <id>` first and `owner <thread>@<generation>` last. When it names another thread, end the turn with no further command. Otherwise set `$B` to `brigade.py --at <restaurant dir> --owner <thread>@<generation>`, and pass `--owner <restaurant>/@<generation>` on every `$L lease claim`, `lease renew`, `lease release`, and `submit`. When `status` prints no owner line and `restaurant.json` records this thread, run `$B set --thread <this thread>` once and read `status` again. A write refused with `is stale` means another thread replaced this one. End the service with no further command.


2. **Take tickets.** Start with `$B inbox take`. It files each ticket a sibling or the executive admin handed to this restaurant, then prints each request from the admin as `A<n>: <line>`. Act on each request per [Reporting to an executive admin](../SKILL.md#reporting-to-an-executive-admin), then run `$B inbox done A<n>`. Each user request or supplier finding becomes `$B ticket add`, with `--source user` or the intake name of the source it came from, such as the tracker AGENTS.md names, and with `--kind`, and the `--ref` that [Filing tracker work](../SKILL.md#filing-tracker-work) gives it. Fetch only the sources in this restaurant's intake. A ticket that is a sibling's work goes to it with `$B ticket move <id> --to <sibling>`. Then call `t3_thread_send` to the thread it prints, with mode `"auto"`, the line `ticket <sibling>: run ticket take`, and the handoff id as `clientRequestId`. The handoff id is this restaurant's store path, the last two parts of `<restaurant dir>`, then the ticket, such as `app/engine/T6`. Fetch supplier sources only when the house rules name them and this restaurant owns them. Read backlog from the tracker that [Filing tracker work](../SKILL.md#filing-tracker-work) names. Read pull requests with `gh pr list` only when the house rules name pull requests and this restaurant owns that source. Read notifications only when the house rules name them and this restaurant owns that source. Drop a ticket that is off the menu with `$B ticket set <id> --state dropped` and say why in the next report. At `digest` a dropped ticket is not a reply occasion.


3. **Group before firing.** Read the waiting tickets together. Several reports of one cause are one dish. Fire a ticket alone only when it is urgent or unrelated to the rest. A ticket that is a whole program with a done predicate runs as one dish whose station is poteto-mode's Orchestrate playbook.


4. **Fire.** Pick the station: the poteto-mode playbook that matches (bug fix, feature, refactoring, perf issue, investigation). Then:

1. `$B fire --tickets ... --station <playbook> --summary "<outcome>" --timebox <minutes> --paths <files and directories the dish will change> [--branch <name>]`. Pass `--mode full --reason "<one line>"` when the tickets name a lock, a lease, a race, a migration, or history rewriting. `fire` is refused when the first ticket has no kind, no `--kind` is passed, and the station is not `bug-fix`, `perf-issue`, or `investigation`. It claims a landing lease on those paths plus the generated copies and doc pages the contract map makes from them when the contract lists generated paths and a map, plus the change-note fragment when the store sets `changeNoteDir`, for holder `<restaurant>/<dish>` before it records anything. `fire` refuses when this restaurant's running workers are already at `--workers`. A refused claim names the holder and fires nothing. A refused `fire` leaves the tickets waiting. Fire refuses a lease holding a shared document from the store's `sharedDocs` catalog when `--timebox` is over the store's `docTimebox`, default 90, or `--tickets` names more than one ticket, unless `--doc-item`. On the first refusal, create the liveness schedule from [First service step 3](../SKILL.md#first-service) if `restaurant.json` has no `liveness` id. Fold the tickets into the holder's dish when it is this restaurant's, or leave them waiting until that lease is released. Never pass `.` for a dish that touches a few files. Size the timebox to the work, 30 to 90 minutes. The timebox follows [Deadlines](../../pstack-runtime/SKILL.md#deadlines).

2. `$B brief <dish> --fields <path>`. The file is the JSON object [Brief fields](../script.md#brief-fields) describes. `--fields -` reads it from stdin. Single-quote every flag value per [The script](../SKILL.md#the-script). Read [Brief fields](../script.md#brief-fields) before you write brief fields. It assembles the brief from the menu, the tickets, the house rules, and the landing rules, names the dish branch, adds the exclusive-slot rule for measuring stations, writes `briefs/<dish>.md`, and uses the picker when verify is omitted. The brief carries the item's `Mode:` lines and `Gate: brigade`. Read its `Mode:` value for steps 4.3 and 6. The report section first tells the worker never to end its turn while a child task it delegated is open, per [the runtime's Delegation section](../../pstack-runtime/SKILL.md#delegation). It gives a thread the worker launched the same bounded wait, except a long-lived owner its playbook supervises, which follows [the runtime's Top-level threads section](../../pstack-runtime/SKILL.md#top-level-threads). It then tells the worker to call `t3_thread_send` on the coordinator thread after the report file is written. It refuses when a field is missing, and when no coordinator thread is recorded. Run `$B set --thread` first. Fix the field. Never hand-write a brief.


### 4.3 Launch detail

Read this before launching the worker in step 4.3.

   3. Launch the worker with `t3_thread_launch`: title `<restaurant> <dish>: <summary>`, `workspaceStrategy: {"type": "worktree", "baseRef": "<trunk>", "branch": "<dish branch from the brief>", "startFromOrigin": true}` (local landing mode: `baseRef` `refs/landing/<trunk>` and `startFromOrigin` false), and the brief file's contents as `message`. Resolve the station's seat with `roles.py show --brief-mode <the Mode: value in briefs/<dish>.md>` and no other mode flag, per [the runtime's Roles section](../../pstack-runtime/SKILL.md#roles), so an item moved to full gets full seats. Build `modelSelection` from that seat per [the runtime's Top-level threads section](../../pstack-runtime/SKILL.md#top-level-threads). Omit `modelSelection` for an `inherit` seat. Confirm the applied options per [the runtime's Delegation section](../../pstack-runtime/SKILL.md#delegation) before step 4.4. Step 4.4 records the thread only after the readback matches. On a mismatch, stop the thread per the runtime, record nothing, and park the dish per [Seat mismatch](../recovery.md#seat-mismatch).


**Refill.** The worker cap is a target, not only a ceiling. After every merge, every passed review, every dropped dish, every liveness check, and every intake run, run `$B startable` in the same turn, before ending it. Take the first ticket line that says `startable`. Fire one dish per steps 3 and 4 with that ticket, every ticket printed as `rides with` it, and `--paths` set to the paths on its line. Pass --doc-item when the line shows --doc-item. Run `$B startable` again and repeat until no ticket line says `startable` or a `fire` is refused. Fire nothing that prints `below auto-start`, `decision for the owner`, or `held back` unless the user says so. For a ticket printed as `unknown, no paths recorded`, run `$B ticket paths` once, or record its files with `$B ticket set T<n> --paths <comma-separated files and directories>`, then read `$B startable` again.


5. **End the turn** while dishes run. A worker's report-back message wakes the coordinator, which marks the dish reported with `$B dish <id> --reported` and reviews it per step 6. The liveness schedule stays as the backstop for a worker that hangs or never sends the message, at the interval it was last created with.
