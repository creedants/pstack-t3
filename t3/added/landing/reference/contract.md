# Stored contract

Read this file before changing init flags or reading stored contract values.

A rerun of `init` keeps the stored checks, setup, batch and timeout whose flag is omitted. A default fills a key only when the contract does not hold that key. With a stored method, an omitted `--merge-method` keeps it while the repository allows it, picks an allowed method when it is not allowed, refuses when the repository allows none, and keeps it when `gh` cannot report the allowed methods. `--author-policy` sets the authorship rule [Run writers through it](../SKILL.md#run-writers-through-it) describes, a first init without the flag stores `any`, and a rerun without the flag keeps a stored value or fills `any` when the key is absent. An unknown `--author-policy` value is refused before the contract changes. `--pr-item-line` sets whether the queue appends the Kind and Goal line to the PR body when the item has one, a first init without the flag stores off, and a rerun without the flag keeps a stored value or fills off when the key is absent. An unknown `--pr-item-line` value is refused before the contract changes. `--heartbeat-ms` sets the fallback schedule interval. `land.py status` names the heartbeat intervals only when either stored interval differs from its default. `--merge-heartbeat-ms` sets the merge wait interval. When status names no heartbeat use 3600000. When it names no merge wait use 900000. A first init without the flag stores 3600000, and a rerun without the flag keeps a stored value or fills 3600000 when the key is absent. A first init without the merge flag stores 900000, and a rerun without the flag keeps a stored value or fills 900000 when the key is absent. A heartbeat value that is not an integer or is below its floor is refused before the contract changes.

`--generated` lists repository-relative paths the queue treats as generated output, as a comma list. `--rebuild` names the command that regenerates them. A new contract stores an empty list and no command. A rerun keeps a stored `generated` and `rebuild` whose flag is omitted, and an empty value clears either. `init` strips trailing slashes, then refuses an absolute path, a path with a `.`, `..`, or empty component, and an empty entry in the list. With no generated paths the queue never refuses a generated-only change, never runs `git rm` or `git clean` for a generated path, and never rebuilds. With generated paths and no rebuild command it refuses a change that touches only those paths, and the refusal says the contract has no rebuild command. With both the queue rebuilds the stored paths with the stored command. `init` and a repo-level `status` print both keys when the contract holds either. A repository that regenerates files keeps that behavior across a rerun with `python3 <skills>/landing/scripts/land.py --repo <checkout> init --trunk main --mode <mode> --generated <paths> --rebuild "<command>"`. A writer needs no lease on generated paths. `submit` leaves them out of the fingerprint and the lease check, and refuses a change that touches only generated paths.

Merge and human mode need GitHub and an authenticated `gh`. Both open a pull request and read its state through `gh`, and merge mode merges it through `gh`. Push mode needs a git remote that accepts a push and opens no pull request. Local mode needs no remote and lands on `refs/landing/<trunk>`. A branch whose protection requires an approving review does not merge unattended, because merge mode pauses on that requirement and names the PR. Use human mode when a person merges every pull request.

In `merge` mode, `init` runs `gh repo view --json mergeCommitAllowed,squashMergeAllowed,rebaseMergeAllowed`. When the contract has no merge method and `--merge-method` is omitted, it stores the only allowed method, or prefers merge, then squash when several are allowed. When `gh` can report the allowed methods, an explicit method the repository disallows is refused, and the error names the allowed methods. When `gh` fails, `init` stores the explicit method, keeps the stored method when the flag is omitted, or defaults to merge when neither exists. When `gh` can report the allowed methods, the method is checked against the repository whenever it is set, in any mode, and whenever the mode becomes merge. `mode merge` swaps a stored method the repository disallows for an allowed one and names it.

The cap belongs to the repository like the mode does. It bounds changes in flight. Those are every submitted lease and every active lease that has not expired, whichever coordinator holds it. The coordinator that opens first sets it with the mode, as `init --trunk main --mode merge --cap 4`, and `land.py cap N` changes it later. A claim at the cap is refused with `repository at its cap: 4 of 4 changes in flight (<holders>)`. `status` shows `changes in flight: 3 of 4` while a cap is set. The executive admin divides the cap into shares with `land.py share`, and `land.py cap N` refuses a positive cap below the current sum of those shares.
